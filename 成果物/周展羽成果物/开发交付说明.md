## 4. 查询口径（评审可能追问的点）

- **列表排序在内存里做，不交给 SQL**：`registered_at` 是 ISO 字符串，毫秒为 0 时会少一段小数（`...42Z` 与 `...42.316Z`），交给 SQLite 排序会让同一秒注册的两条排错序。改为取出后按 `(注册时间倒序, id 倒序)` 排，用自增 id 兜底——与交易模块队列"按 (submittedAt, id)"排序同一思路。
- **历史与买家端逐字一致**：购买历史与 `CustomerService.history()` 用**同一条查询、同一套换算**（成功之外一律记失败）。两边各写一份迟早会漂，共用一套就没有这个问题；这也是 FR-S-14 验收标准第 3 条的要求。
- **只列终态**：`queued` / `trading` 的意向不出现在购买历史里（SRS BR-16：只含成功 / 失败）。
- **字段就四项**：没有"姓名"列（SRS 数据字典里客户只有用户名 / 密码 / 电话 / 地点 / 注册时间）；未填地点显示"未设置"。
- **不做的事**（EX-06）：编辑、禁用、删除、导出、搜索、筛选一律没有——纯只读。

## 6. 已知限制

1. **客户列表排序 / 翻页方式是本轮约定**（SRS T-21 待确认项）：按注册时间倒序 + 每页 10 条，不作为验收依据。
2. **同一秒注册的客户顺序靠 id 兜底**：id 即注册先后，结果正确，但严格说排序键是"时间 + id"。
3. **历史里的商品名是快照**：商品改名后历史仍显示下单时的旧名（这是 SRS BR-36 的要求，不是缺陷）。
4. **无法看到"哪些客户从未下过单"的汇总**：列表与历史是两个页面，没有关联统计（超出需求范围，未做）。
