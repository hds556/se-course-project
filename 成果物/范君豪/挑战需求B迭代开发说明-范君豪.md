2. 我的收藏列表：按收藏时间倒序，展示名称、价格、主图、收藏时间、在售状态。

5. 商品详情页实时反映收藏状态，按钮在「收藏 / 取消收藏」之间切换。

### 2.2 购物车（14202）
1. 加入购物车；同一客户 + 同一商品**只有一行**，重复加购累加数量（数据库唯一索引兜底）。
2. 修改数量（小于 1 拒绝）、移除条目，均限制为本人购物车项。
3. 加购不校验也不扣减库存，商品可售库存数字不因加购而变化。
4. 已下架商品条目保留、整行置灰、复选框禁用、数量与移除以外的操作禁用。
5. 前端实时显示勾选件数与合计金额。

### 2.3 提交订单（14203）
1. 从购物车勾选任意件数商品提交，**只生成 1 笔订单**，内含多条明细。
2. 下单逐条执行**条件扣减**（`WHERE stock >= 数量`），库存不足影响行数为 0，杜绝负库存与超卖。
3. **逐商品校验**：缺货或已下架的商品被剔除并给出具体原因，其余商品照常生成订单；若全部不可下单则整体返回 409 且不生成订单。
4. 明细保存下单快照（商品名称、单价），之后卖家改价不影响历史订单。
5. 总金额由服务端按 Σ(单价 × 数量) 计算，不信任前端传值。
6. 下单成功后仅删除本次成功下单的购物车项，未勾选与缺货项保留。
7. 已下架商品不参与下单，也不会被自动从购物车删除。

### 2.4 客户取消订单（14204）
1. 「客户下单 / 商家确认 / 备货完成」三种状态下显示「取消订单」按钮；「开始发货 / 交易完成 / 已取消」不再提供入口。
2. 点击即生效：不弹确认框、不填取消原因、不记录取消时间。
3. 取消时按明细数量逐项回补库存；若商品因售罄曾被自动下架，库存恢复为正后自动回到在售状态（手动下架的 `withdrawn` 不受影响）。
4. 后端做状态兜底校验：非可取消状态返回 409；他人订单返回 404。
5. 取消后列表即时刷新为「已取消」并给出提示。

### 2.5 查看我的订单（14205）

> 说明：上一次迭代已有「历史下单记录」页 `orders.html`（数据源是购买意向，只展示有交易结果的终态记录，按下单时间倒序分页）。本需求是在该页基础上**改造**为订单制视图，不是从零新建页面；下面只列这一次的改造点。

2. **改造**展示范围：由「只展示有交易结果的记录」改为展示本人**全部**订单，含进行中、交易完成、已取消。
3. **新增**状态维度：每条订单显示状态标签（客户下单 / 商家确认 / 备货完成 / 已发货 / 交易完成 / 已取消）。
4. **改造**列表行信息：由「商品名称 / 下单时间 / 交易结果 / 交易时间」改为订单维度的「订单号 / 商品种数 / 总金额 / 状态」，并**新增**行内展开的多行明细（商品名称、下单单价、数量、小计）。

## 三、实现思路与关键技术方案

### 3.1 领域模型：订单制取代「购买意向」

迭代 1～3 的买家成交记录建立在「购买意向（intent）」模型上：一个商品对应一条意向记录，没有「一次提交多件商品」的概念。挑战需求 B 要求「多件商品生成 1 笔订单并整单流转状态」，意向模型无法表达，因此按 SRS §6 新建 4 张表：

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `orders` | 订单主表：客户、总金额、状态、下单时间 | 只有**下单时间**一个时间戳，无地址字段；状态整单流转 |
| `order_item` | 订单明细：商品、名称快照、单价快照、数量 | 数量 ≥ 1；名称与单价在下单时固化 |
| `cart_item` | 购物车项：客户、商品、数量 | `(customer_id, product_id)` 唯一索引；与库存无关 |
| `favorite` | 收藏：客户、商品、收藏时间 | `(customer_id, product_id)` 唯一索引 |

订单状态用枚举 `OrderStatus` 表达：`placed → confirmed → packed → shipped → completed` 顺序推进，`cancelled` 为独立终态。枚举通过 `AttributeConverter` 以小写 code 落库，让列类型为 `varchar`，避免 Hibernate 为枚举列生成 SQLite 不支持的 check 约束。

### 3.2 库存一致性：把「判断 + 扣减」压进一条 SQL

下单扣库存是最容易出问题的点。若先 `select stock` 再 `update stock = stock - n`，两个并发请求可能都读到「库存 1」而各自扣减，造成超卖与负库存。因此扣减写成条件更新：

```sql
update product set stock = stock - :qty, version = version + 1
 where id = :id and stock >= :qty and status in ('active', 'resumed')
```

- `stock >= :qty` 在数据库层完成判断，库存不足时受影响行数为 0，调用方据此判定缺货；
- 判断与扣减在同一条语句内，天然原子，不会出现「判断通过后库存被抢走」的窗口；
- 同时要求 `status` 在售，避免对已下架商品下单。

在应用层再叠一把公平可重入锁，锁的范围覆盖**整个事务提交**（`TransactionTemplate`），因此「校验 → 扣减 → 建订单 → 删购物车项」在进程内串行；数据库条件更新则是第二道防线，即便绕过锁也不会扣成负数。测试用例 `concurrentSubmitNeverOversells` 用 8 个并发买家抢 5 件库存，验证恰好 5 单成功、库存归零不为负。

### 3.3 逐商品校验而非整单拒绝

提交订单采用「逐商品」而非「整单」判定：遍历勾选项，已下架或库存不足的记入 `rejectedItems`（key = productId），其余正常扣减并写入订单。只有**全部**失败时才整体回滚并返回 409。这样 5 件商品里 1 件缺货不会让另外 4 件白忙一场，符合需求文档中「仅剔除缺货商品、其余照常下单」的验收要求。异常类 `OrderException` 特意**不继承** `ResponseStatusException`——后者自带 `detail` 字段，会被 Spring 内建的 `ResponseStatusExceptionResolver` 抢先处理成 problem+json，附加的 `itemErrors` 会丢失。

### 3.4 快照与金额计算

明细在下单瞬间把 `productName` 与 `unitPriceCents` 拷贝进 `order_item`，之后的改价/改名不影响历史订单。订单总金额由服务端按 `Σ(明细单价 × 数量)` 计算后落库，前端传入的价格一律不采信。

### 3.5 取消订单的库存回补

取消时按明细逐项执行 `restoreStock`：`stock = stock + qty`，并把 `status = depleted` 的商品改回 `active`（售罄下架 → 可售恢复为正 → 在售）。只针对售罄成因，手动下架 `withdrawn` 不受影响，避免「取消一笔订单把卖家手动下架的商品偷偷上架」。

### 3.6 越权防护：从接口形态上排除

客户侧订单接口只接受 `customer_session` 会话，**不接受前端传 customerId**；仓储层不提供「只按 id 查订单」的入口，只有 `findByIdAndCustomerId`。因此他人订单号一律表现为「订单不存在」，既不泄露订单是否存在，也无需在业务代码里逐处写权限判断。

### 3.7 前端状态一致性的几个具体处理

- 下单唯一入口在购物车页，详情页只提供「加入购物车」，不提供「立即购买」，落实「购物车是唯一下单入口」。
- 已下架商品在购物车/收藏中**不被自动删除**，只做置灰与禁用，符合「条目保留、不可下单」。
- 逐商品缺货原因存在 `itemErrors` Map 中，列表刷新（re-render）后重新回填到对应行，避免被刷新冲掉。
- 取消订单按钮位于 `<details><summary>` 内，同时拦截 `mousedown` 与 `click` 的默认行为，防止点击按钮时顺带折叠订单。
- 购物车/收藏/订单页的内联脚本先于 `defer` 的公共脚本执行，因此统一在 `DOMContentLoaded` 之后再调用公共函数。

## 五、开发与验证过程

1. **需求与数据模型梳理**：对照 SRS §5.4（订单状态）、§6.5～6.8（订单/明细/购物车/收藏）确定 4 张表与字段，明确「订单只有下单时间、无地址」「状态整单流转、不逐商品流转」等硬约束。
2. **后端自底向上实现**：先落实体与仓储，再写 `OrderService`（含库存条件扣减与逐商品校验），最后暴露 `OrderController`。每一步用 `mvn -o compile` 编译确认。
3. **测试驱动收敛细节**：编写 20 条集成测试覆盖各需求的验收标准，过程中发现并修正三类问题：
   - 控制器源文件写入中断导致路由整体 404，重新写入并核对编译产物；
   - `OrderException` 继承 `ResponseStatusException` 时 `itemErrors` 被内建解析器吞掉，改为独立异常类型；
   - 测试里 `jsonPath("$.itemErrors.1")` 会把数字键当数组下标，改用 `has()` 断言。
4. **前端实现与联调**：新建购物车、收藏两个页面，改造详情页与订单页，在浏览器中逐页走查，修正了三处真实缺陷：
   - 内联脚本早于 `defer` 公共脚本执行导致 `ReferenceError: currentCustomer is not defined`，改为 `DOMContentLoaded` 后初始化；
   - 取消订单按钮被 `<summary>` 的默认折叠行为拦截，补齐 `mousedown`/`click` 的默认行为拦截；
   - 逐商品缺货标记在列表刷新后被冲掉，改为用 `itemErrors` 记状态、渲染后重新回填。
