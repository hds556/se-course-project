## 三、各需求的实现要点

### 14257 支付订单（FR-C-09）

**状态流转**：`客户下单 → 待支付 → 已支付`

1. **发起支付**：客户在订单页点「去支付」进入模拟支付页，选择四种渠道之一（银行卡 / 信用卡 / 支付宝 / 微信支付，BR-52），订单进入「待支付」并记录所选渠道。
2. **模拟支付**：不接真实网关（EX-02 / BR-54），由 `success` 标志模拟结果：
   - 成功 → 订单转「已支付」，支付渠道落库（供原路退款使用，IC-11）；
   - 失败 → 订单**停留「待支付」**，不设独立失败状态，可重新发起（规则 4），不影响库存。
3. **幂等**：支付成功与否都用条件更新 `WHERE status IN (placed, pending_payment)` 抢占，重复提交 / 并发提交只有一笔生效，其余返回 `idempotent=true`，**不产生第二笔扣款**（BR-55 / AC-14）。已支付及之后状态无支付入口。
4. **24h 超时自动取消**（BR-21 / S-11）：以下单时间起算，`PaymentTimeoutJob` 定时扫描（默认 60 秒一轮），将超时未支付订单转为「已取消」并按明细数量回补库存；因售罄下架的商品随库存恢复自动回到在售（BR-04 / BR-27）。
   - 超时取消与客户支付共用同一把写锁 + 条件更新，谁先拿到订单谁生效，**杜绝「已付款却仍被取消」的资损**（BR-57）；
   - 另在支付入口做兜底判断：即使扫描尚未执行，超时订单也拒绝支付并提示。
5. **与取消的衔接**（BR-17）：未付款段（客户下单 / 待支付）取消无退款；已付款段（已支付 / 商家确认 / 备货完成）取消按订单记录的渠道**原路退款**，退款金额为订单总额（明细快照合计）。

### 14258 确认收货（FR-C-11）

1. 仅「开始发货」状态可确认收货，按钮由后端 `confirmable` 字段驱动，前端不自行推断状态机。
2. 点击后经一次确认提示（终态不可逆），订单转「交易完成」，不可回退、不可再取消（BR-13）。
3. 对已「交易完成」的订单重复确认按幂等返回 `idempotent=true`，不报错、不重复流转。
4. **无任何自动确认**：无物流签收自动触发、无超时自动确认（EX-09），只能由客户点击。

### 14259 查询物流（FR-C-12）

1. 只有发货后（「开始发货」「交易完成」，以及发货后被取消的订单）才有物流信息；未发货订单返回「暂无物流信息」，不泄露任何单号。
2. 展示物流单号、物流公司、发货时间与跟踪轨迹（BR-60）。
3. **跟踪信息为模拟数据**（S-16）：枚举固定「已发货 / 运输中 / 已签收」三档，由发货时间与当前时间之差推算（交运即已发货、满 1 天运输中、满 3 天已签收），同一订单反复查询轨迹只前进不倒退，无需额外轨迹表。
4. 我的订单列表同时展示物流单号，符合 FR-C-16 的订单信息要求。

### 安全与越权（AC-10 / 验收 3）

客户侧全部接口只按「登录客户 + 订单号」定位订单（`findByIdAndCustomerId`），不提供只按 id 的入口；他人订单号统一返回 404「订单不存在或无权访问」，未登录返回 401。

## 五、测试与验证

`PaymentShippingIntegrationTest` 覆盖三条需求的主要验收标准，共 **22 个用例**，全部通过。

| 需求 | 覆盖点 |
|---|---|
| 支付 | 下单→待支付；四渠道均可用、非法渠道/未选渠道拒绝；支付成功→已支付并记录渠道；支付失败停留待支付且可重试；重复支付幂等；并发支付只结算一次；超 24h 自动取消并回补库存、售罄商品恢复在售；已支付不被超时取消；超时后拒绝支付；已支付及之后无支付入口；他人订单不可支付 |
| 确认收货 | 开始发货→交易完成；非开始发货状态不可确认；交易完成为终态、重复确认幂等；无自动确认；他人订单不可确认 |
| 查询物流 | 已发货可见单号与轨迹；轨迹随模拟时间推进；未发货无物流信息；交易完成/发货后取消仍可查；他人订单不可查 |
| 取消衔接 | 未付款段取消无退款；已付款段取消原路退款并回补库存 |

验证方式说明：截图数据通过真实接口操作产生（注册、上架商品、加购下单、支付），卖家「开始发货」环节因该需求的表单与校验归开发 C，截图时直接写入物流字段以构造场景，未改动卖家实现。

## 七、遗留与协作说明

1. **卖家开始发货时的物流单号录入**：物流字段在订单表内的写入入口已由我提供（`changeStatusToShipped`），但「开始发货」表单、单号必填校验属 14207（开发 C）的实现范围，本次未越界实现；若该需求实现时需要，可直接调用该入口以保证「状态 + 单号」原子写入。
2. **收货地址快照**：物流模拟轨迹的文案会读取订单的地址快照用于生成城市名，地址簿由开发 C 在本次迭代实现。为避免占用对方数据所有权，我按字段名反射读取，字段不存在时自动回退为通用文案。
3. **物流为模拟数据**：按 SRS S-16 口径实现，未接真实物流 API；后续若接入真实快递接口，只需替换 `LogisticsSimulator` 的实现，接口出参与页面无需改动。
