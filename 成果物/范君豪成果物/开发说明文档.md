## 1. 任务范围

1. **FR-C-04 客户注册**：用户名、密码、电话必填；默认交易地点选填；用户名唯一、电话不唯一；密码 ≥ 8 位；无验证码。
2. **FR-C-05 客户登录**：凭用户名 + 密码登录；电话不作登录凭证；提供退出登录。
3. **FR-C-07 查看历史下单记录**：登录后可用；只展示已有交易结果（成功/失败）的终态记录；展示商品名称（快照）、下单时间、交易结果、交易时间；按时间倒序、支持翻页；只读不可删除。

> 下单（FR-C-06）、卖家侧客户管理（FR-S-13/14）不属于本次任务。

## 2. 后端实现

### 2.1 新增文件

| 文件（`src/main/java/com/coursewise/shopping/` 下） | 职责 |
|---|---|
| `domain/CustomerEntity.java` | 客户实体（表 `customer`） |
| `repository/CustomerRepository.java` | `findByUsername`、`existsByUsername` |
| `customer/CustomerService.java` | 注册校验、登录/会话、`me`、历史查询 |
| `customer/CustomerException.java` | 客户模块业务异常（HTTP 状态 + 字段级错误） |
| `customer/CustomerController.java` | REST API（见 2.2） |

### 2.2 REST API

| 方法与路径 | 说明 | 鉴权 |
|---|---|---|
| `POST /api/customer/register` | 注册，成功 201；不自动登录 | 免登录 |
| `POST /api/customer/login` | 登录，成功后 `Set-Cookie: customer_session`（HttpOnly, SameSite=Strict） | 免登录 |
| `GET /api/customer/me` | 当前登录客户信息（未登录 401） | Cookie |
| `POST /api/customer/logout` | 退出登录并清除 Cookie | Cookie |
| `GET /api/customer/orders?page=&size=` | 历史下单记录，分页（默认每页 10、上限 50），按下单时间倒序 | Cookie |

历史记录响应结构：

```json
{ "items": [ { "id":1, "productId":2, "productName":"测试保温杯",
    "submittedAt":"2026-10-30T04:10:00Z", "result":"失败",
    "closedAt":"2026-10-30T04:40:00Z" } ],
  "page":1, "size":10, "total":2, "totalPages":2 }
```

## 3. 数据库

数据库为 SQLite 单文件 `data/shop.db`，由 Hibernate 按 `ddl-auto=update` 在启动时自动建表/补列，**无需手工执行 SQL 脚本**；开发开始前已重置数据库排除旧数据影响。本次涉及：

### 3.1 新增表：customer（§5.3）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | integer | 主键，自增 | |
| username | varchar(64) | NOT NULL，**UNIQUE** | 登录凭证（BR-14）；允许与卖家同名 |
| password_hash | varchar(255) | NOT NULL | scrypt 哈希，不存明文 |
| phone | varchar(32) | NOT NULL | 不唯一（C-8），不作登录凭证 |
| default_place | varchar(200) | 可空 | 默认交易地点 |
| registered_at | varchar(32) | NOT NULL | 注册时间，系统记录 |

### 3.2 变更表：intent（§5.4）新增两列（原有列不动）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| customer_id | bigint | 可空，索引 `idx_intent_customer` | 关联客户；为 NULL 表示匿名意向，不迁移、不展示、不进客户历史。FR-C-06 下单方实现后写入 |
| closed_at | varchar(32) | 可空 | 交易时间：标记交易结果那一刻的时间戳，未终结时为 NULL |

### 3.3 既有代码的最小必需改动

- `domain/IntentEntity.java`：新增上述 `customer_id`、`closed_at` 两列与索引。
- `repository/IntentRepository.java`：新增 `findByCustomerIdAndStageOrderBySubmittedAtDescIdDesc`。
- `ShoppingService.java`：在三处意向结案点（交易成功含其余未成交作废、交易失败作废/重排结案、买家撤销）写入 `closedAt`，保证"交易时间"字段完整；未改动任何既有业务规则。

### 3.4 关键查询与快照口径

- 历史查询：`intent WHERE customer_id=? AND stage='closed' ORDER BY submitted_at DESC, id DESC`，关联 `product` 取商品名。
- 结果映射（历史只有成功/失败两档，BR-34/37）：`success → 成功`，其余终态（作废/重排/撤销/未成交）→ `失败`。
- 商品名快照：商品名发布后不可改（BR-29）、商品永不删除（BR-28），直接取商品表名称即等价于下单时快照；商品下架后记录照常展示（FR-C-07）。

## 4. 前端实现

| 文件 | 说明 |
|---|---|
| `public/register.html` | 注册页：用户名/密码/确认密码/电话/默认交易地点（选填）；前端先校验两次密码一致，后端字段级错误直接展示；成功后跳登录页 |

| `public/index.html` | 头部导航新增：我的订单、客户登录、注册；并根据登录态切换显示（当前用户 / 退出登录） |
| `public/catalog.css` | 新增 `header nav` 规则，使导航按钮间距分隔 |

## 5. 会话存储

客户登录会话不落库：token → customerId 存内存，通过 HttpOnly Cookie `customer_session` 携带，重启失效需重新登录（与卖家会话同口径）。

## 7. 与其他需求的衔接

- **下单（FR-C-06）不在本次范围**。下单方实现时，只需在提交意向处为 `IntentEntity` 填入 `customerId`，即可打通"注册 → 登录 → 下单 → 查历史"全流程，历史模块无需再改。
- 卖家侧查看客户列表/购买历史（FR-S-13/14）不在本次范围，但 `customer` 表字段（用户名/电话/默认交易地点/注册时间）已按需求定义预留完整。
