# 接口与联调约定

## 下单与查询

| 方法路径 | 请求/响应 |
|---|---|
| GET /api/checkout/addresses | customer_session；返回items:[{id,addressText,isDefault}]，只返回本人地址 |
| POST /api/checkout/addresses | {addressText}，确认页最小地址新增，首条默认；完整地址管理由开发C提供 |
| POST /api/orders/preview | {cartItemIds:[1,2],addressId:3}；返回canSubmit、itemErrors（商品ID到原因）、readyCartItemIds、addressSnapshot、totalCents；不扣库存、不建单 |
| POST /api/orders | 同上，addressId省略时取默认；201单笔订单（可含多明细），带message及24h截止信息；无地址400，混入他人购物车/地址404，缺货409带itemErrors |
| GET /api/orders?page=1&size=10 | 本人全部订单倒序分页；每项含items、addressSnapshot、支付物流摘要与操作许可 |
| GET /api/orders/{id} | 只允许本人查看，越权404 |
| POST /api/orders/{id}/cancel | 不要求请求体、原因或确认；200含refunded/refundCents/refundChannel；不可取消409 |

所有客户接口使用customer_session，不接受客户端指定customerId。amount等金额字段不参与服务端计算。购物车预检是建议，不是最终库存承诺。

订单视图新增：addressSnapshot（旧订单可null）；refund（无退款为null，有退款为{id,amountCents,channel,channelLabel,status,simulated:true}）。

## 数据表与成员协作

- orders新增address_snapshot，旧库可平滑新增可空列，新订单服务强制非空。由B落单时写入，之后只读。
- address按SRS §6.4，字段id/customer_id/address_text/is_default/created_at。CheckoutAddressService为B适配层；C完整地址管理请复用实体与Repository或仅替换适配层。相同customer_id最多一个默认地址；当前最小新增在共享写锁内维护。
- order_refund为模拟退款回执，order_id唯一，pay_channel、amount_cents、status=succeeded、created_at。本模块只写客户取消退款。C卖家取消、D售后退款需要各自明确幂等键与金额规则，不能不经设计直接复用“一单取消一条”来处理所有售后明细退款。
- 支付A已提供pay_channel和支付状态；B为列表摘要增加payment_captured成功标记，和原markPaid条件更新一起置true，取消不清除。发货C提供tracking_no/ship_company，B只读。待支付已选渠道不代表支付成功，订单摘要不应把它显示为已付款渠道。
- 订单渠道摘要以支付成功标记、当前已付款状态或已有退款回执判断，卖家取消后也保留已支付渠道；退款明细摘要仍以各模块持久化的回执为准。
- 商品库存写入口沿用ProductRepository.deductStock/restoreStock，不新增状态机。

## 升级与运行

JDK17；`./mvnw.cmd test`；`./mvnw.cmd package`；`java -jar target/shopping-system-1.0.0.jar`。默认端口3000。
正式库升级前由部署负责人备份数据库与uploads。构建的ddl-auto=update沿用工程配置，新增地址表、退款表与地址快照列；不补写不可靠的历史地址。
