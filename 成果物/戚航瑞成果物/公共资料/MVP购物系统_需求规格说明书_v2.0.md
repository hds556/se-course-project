## 文档说明与阅读约定

1. **编号沿用**：本版沿用 V3.5 已建立的编号体系——功能需求 `FR-C-xx`（客户侧）/ `FR-S-xx`（卖家侧）、业务规则 `BR-xx`、范围外 `EX-xx`、待确认 `T-xx`、冲突纠正 `C-xx`。编号不因重排而改变，便于与需求分析文档对照。

## 1. 引言

### 1.1 编写目的

本文档在需求分析文档 V3.5 的基础上，将需求转化为**完整、无歧义、可验收**的规格条款，明确系统必须提供的功能、必须满足的业务规则、必须遵循的状态流转与必须持有的数据，作为设计、实现与验收的唯一依据。

### 1.2 适用范围

本系统是一个**可同时发布多件商品**的极简在线购物系统，服务**一名卖家**与**多名注册客户**：

- 卖家在后台维护类别、发布商品、管理库存、按先来后到与客户线下交易、查看客户与历史。
- 客户注册登录后浏览或搜索商品、提交购买意向（下单）、查看自己的历史下单记录。
- 交易在线下完成（一手交钱一手交货），**系统不涉及在线支付与物流**。

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| 在售 | 商品可被浏览、可被搜索、可提交意向的状态 |
| 已冻结 | 卖家正与队首客户交易中，该商品停止接受新意向；**只锁该件商品**，不影响其他商品。本版**仅由发起交易自动触发** |
| 已下架 | 商品退出买家端的状态，有三种成因：交易成功下架（已售）、库存为 0 自动下架（售罄）、卖家手动下架 |
| 售罄 | 专指"**库存归零但没有成交**"触发的自动下架；补货后可重新上架 |
| 手动下架 | 卖家主动将在售或已冻结商品撤下的操作；**本轮无重新上架路径**（EX-14） |
| 售罄重新上架 | 仅适用于售罄商品的恢复操作（FR-S-07），与"手动上架"不是同一功能 |
| 意向 / 下单记录 | 客户提交购买意向即生成一条下单记录（下单时间＝提交时间），交易结果后续更新为成功 / 失败 |
| 队首 | 同一商品队列中最早提交且未终结的意向；卖家发起交易时**强制取队首** |
| 主图 | 该商品**第一张**上传的图片，用于列表与搜索结果展示；无图时显示占位图 |
| 富媒体 | 商品描述支持富文本格式与内嵌图片；禁止脚本、交互控件、复杂表格、公式（视频见 T-4） |
| 快照 | 下单记录中保存的**下单当时**的商品名（及类别），此后商品改名或下架不影响其显示 |
| 默认交易地点 | 客户注册时选填的线下交割地点，供交易联系使用 |

## 2. 总体描述

### 2.1 系统角色

| 角色 | 说明 | 主要能力 |
|---|---|---|
| 游客 | 未注册未登录 | **可浏览、可搜索**；**不能提交购买意向** |
| 注册客户 | 注册后凭**用户名 + 密码**登录 | 提交购买意向（下单）、查看自己的历史下单记录 |
| 卖家 | 系统唯一管理账号，凭用户名 + 密码登录后台 | 商品、类别、库存、交易、客户的全部管理 |

> 注册字段是**用户名**（不是姓名）；客户**不能自助修改资料**、**不能撤销意向**、**不能注销账号**（FR-C-08）。

### 2.2 用户特征

- 客户：线下买家，使用浏览器完成"注册 → 登录 → 浏览/搜索 → 下单 → 查历史"；交易环节在线下完成，系统只承担信息登记与撮合。
- 卖家：单人运营，需要按先来后到处理排队、线下交割后回系统标记结果。

### 2.3 约束与假设

| 编号 | 约束 / 假设 |
|---|---|
| CON-1 | 系统只有**一名卖家**，卖家账号不提供自助注册入口 |
| CON-2 | 交易**线下完成**，系统不处理在线支付、不处理物流（BR-25） |
| CON-3 | 系统为 Web 应用，客户端为浏览器；不要求移动端适配 |
| CON-4 | 客户提交意向后**没有自助撤销入口**，"撤销"终态在本版不存在 |
| CON-5 | 商品**不可删除**，退出销售只能走三种下架（BR-28、EX-12） |
| CON-6 | 注册前的匿名意向（口令码时代遗留数据）**不迁移、不展示**（BR-13、T-38） |

### 3.1 客户侧功能需求

#### FR-C-01 浏览商品

- **前置条件**：无。本功能**免登录**可用。
- **规则**：
  1. 系统应提供商品列表页，默认列表**只含在售商品**；已冻结与已下架商品**不应**出现在列表中。
  2. 列表卡片应展示：**商品名称、价格、主图、所属类别**；**不应**展示商品描述，也**不应**展示库存状态（库存仅在详情页展示，见 FR-C-03）。
  3. 系统应支持**按二级类别筛选**浏览。
  4. 列表排序应按**发布时间**排列（倒序，见 T-8 同类口径）。
  5. 系统应支持翻页；每页条数取合理默认值（T-5）。
- **验收标准**：
  1. 未登录状态下可打开商品列表页并看到全部在售商品。
  2. 一件处于"已冻结"或"已下架"的商品，在列表中检索不到。
  3. 列表卡片字段恰好为名称、价格、主图、类别四项，不出现描述正文与库存数字。
  4. 按某一级类别下的二级类别筛选后，结果只含挂在该二级类别下的在售商品。
  5. 商品无图时，卡片主图位置显示占位图而非空白或碎图图标。

#### FR-C-02 搜索商品

- **前置条件**：无。本功能**免登录**可用。
- **规则**：
  1. 系统应提供搜索入口，匹配字段为**商品名称 + 商品描述**；描述应先剥离富文本标签、按纯文本匹配。
  2. **类别不应参与搜索匹配**（类别只用于筛选，见 FR-C-01）。
  3. 搜索结果**只含在售商品**。
  4. 结果卡片字段与列表一致：名称、价格、主图、所属类别。
  5. 匹配方式为模糊包含、不区分大小写；结果按发布时间倒序；空关键词返回全部在售；无结果给出明确提示（T-6 ~ T-8）。
- **验收标准**：
  1. 未登录状态下可执行搜索并返回结果。
  2. 用某商品描述中的一段纯文本（不含标签字符）作为关键词，能搜到该商品。
  3. 用某二级类别名作为关键词，**搜不到**仅因属于该类别而名称与描述不含该词的商品。
  4. 搜索结果中不包含已冻结或已下架的商品。
  5. 搜索无匹配时页面给出明确的"无结果"提示，而非空白列表。

#### FR-C-03 查看商品详情

- **前置条件**：无（在售商品免登录可看）。
- **规则**：
  1. **在售商品**：详情页应展示名称、价格、富媒体描述、**全部商品图**、所属类别、**库存状态**。
  2. **已冻结商品**：**不应**出现在列表与搜索结果中；唯一合法入口是**直链**（详情页 URL / 分享链接）。通过直链打开时页面应为**只读**——可看全部图，但**不能提交购买意向**，且应明示当前状态。
  3. **已下架商品**（含售罄、已售、手动下架）：买家端**不应**能打开详情页，**不应**能提交意向。
  4. 详情页应能查看该商品的**全部**图片（至少可按序逐张看完，T-22）。
- **验收标准**：
  1. 在售商品详情页同时出现价格、库存状态、富媒体描述与全部商品图。
  2. 已冻结商品的详情页通过直链可打开，且页面上没有可提交意向的入口。
  3. 已下架商品的详情 URL 在买家端返回不可访问（404 或"商品不存在"提示），且不可提交意向。
  4. 详情页能依次浏览到第 2 张及以后的商品图，不只能看到主图。

#### FR-C-04 注册

- **前置条件**：游客。
- **规则**：
  1. 注册表单字段：**用户名（必填）、密码（必填）、电话（必填）、默认交易地点（选填）**。
  2. 密码长度**不少于 8 位**；复杂度只校验长度（T-9）。
  3. **用户名必须唯一**，注册时校验，重复则拒绝并提示（提示文案见 T-24）。
  4. **电话不唯一**，一个手机号可注册多个账号；**无短信/图形验证码**环节。
  5. 用户名长度与字符范围不设额外限制，仅要求非空且唯一（T-10）；电话不校验格式，仅要求必填（T-11）。
  6. 注册成功后**不自动登录**，客户需自行登录（T-12）。
- **验收标准**：
  1. 缺填用户名、密码、电话任一项时，注册被拒绝并给出字段级提示。
  2. 不填默认交易地点可注册成功，该客户在卖家客户列表中地点显示为"未设置"或空。
  3. 密码少于 8 位时注册被拒绝。
  4. 使用已存在的用户名注册时注册被拒绝，并提示该用户名已被占用。
  5. 使用同一电话号码注册第二个不同用户名的账号，注册成功。
  6. 注册完成后客户处于未登录状态，需执行登录才能下单。
  7. 注册后系统不提供修改上述任何字段的入口（FR-C-08）。

#### FR-C-05 登录

- **前置条件**：已注册客户。
- **规则**：
  1. 客户应凭**用户名 + 密码**登录；**电话不作为登录凭证**。
  2. 登录失败时统一提示"用户名或密码错误"，不做失败次数限制与账号锁定（T-13）。
  3. 系统应提供**退出登录**（T-12）。
- **验收标准**：
  1. 输入正确的用户名与密码可登录成功。
  2. 输入已注册客户的电话 + 正确密码，**不能**登录成功。
  3. 密码错误与用户名不存在两种情况返回**相同**的提示文案，不泄露账号是否存在。
  4. 登录后可执行下单；退出登录后回到游客状态，下单入口不可用。

#### FR-C-06 提交购买意向（下单）

- **前置条件**：已注册并登录；目标商品处于**在售**状态。
- **规则**：
  1. **必须登录才能提交**；未登录用户点击购买入口时，系统应引导至注册 / 登录页。未登录用户**不应有任何提交意向的通道**（原口令码入口随机制废除，不应出现在界面上）。
  2. 一单**固定 1 件**，不允许一次购买多件（BR-06）。
  3. 提交成功即生成一条**下单记录**，挂在客户账号下，下单时间＝提交时间。
  4. 意向信息**直接取自账号**（用户名、电话），客户**不应有"修改意向信息"的入口**。
  5. 同一账号对同一商品**可重复提交**，不做去重，每条为独立记录、按提交时间排队（BR-07）。
  6. 提交**不预占库存、不扣减库存**（BR-02）。
  7. 已冻结、已下架商品**不应**能提交意向。
- **验收标准**：
  1. 未登录访问商品详情页时，页面无可用下单入口，或点击后跳转至注册 / 登录页。
  2. 登录后提交意向成功，客户的下单记录中立即出现一条记录（此时尚无交易结果）。
  3. 同一账号对同一商品连续提交 2 次，生成 2 条独立记录，卖家队列中可见 2 条且按时间排序。
  4. 提交意向后，商品库存数字不变。
  5. 对已冻结商品（用直链打开）提交意向，操作不可行。

#### FR-C-07 查看历史下单记录

- **前置条件**：已登录客户。
- **规则**：
  1. 系统应提供"我的历史下单记录"页面，**只展示已有明确交易结果（成功 / 失败）**的记录；排队中与交易中的记录**不应**出现（T-3 临时边界下买家端不展示进行中意向）。
  2. 每条至少展示：**商品名称（快照）、下单时间、交易结果、交易时间**；**不应**包含价格、图片、排队位次，也**不应**泄露同队列其他客户的信息。
  3. 列表按**时间倒序**排列，支持翻页（每页条数取默认值，T-16）。
  4. 记录**只读、不可删除**；商品下架后仍照常可看，商品名显示**下单时的快照**。
  5. 不做单条详情页、不做筛选与搜索（EX-08）。
- **验收标准**：
  1. 登录后打开历史页，只看到结果为成功或失败的记录；刚提交、尚无结果的记录不出现。
  2. 每条记录可见商品名、下单时间、交易结果、交易时间四项。
  3. 某商品成交后卖家将其改名，客户历史中仍显示下单时的旧商品名。
  4. 列表中不存在删除按钮或其他删除途径。
  5. 记录按时间倒序排列，最新的在最前。

#### FR-C-08 不提供的客户侧能力（约束性条款）

系统**不应**向客户提供以下能力：

1. **修改个人资料**：用户名、电话、默认交易地点注册后均不可改（改密码仅卖家有，见 FR-S-02）。
2. **撤销意向**：客户无撤销入口，"撤销"终态在本版不存在。
3. **注销账号**：客户无注销入口。

- **验收标准**：注册客户的界面中不出现修改资料、撤销意向、注销账号的入口；通过直接访问相关 URL 也无法执行相应操作。

### 3.2 卖家后台功能需求

#### FR-S-01 登录后台

- **前置条件**：无。
- **规则**：卖家应凭用户名 + 密码登录后台；**未登录不得访问任何后台页面**。
- **验收标准**：未登录直接访问任意后台 URL 时被拦截并跳转至登录页。

#### FR-S-02 修改密码

- **前置条件**：已登录卖家。
- **规则**：修改密码须**先验证原密码**；新密码**不少于 8 位**。
- **验收标准**：
  1. 原密码填写错误时改密失败，密码不变。
  2. 新密码少于 8 位时改密失败。
  3. 改密成功后，用旧密码登录失败、用新密码登录成功。

#### FR-S-03 类别管理

- **前置条件**：已登录卖家。
- **规则**：
  1. 系统应支持类别的**新增、重命名、删除**。
  2. 类别为**两级结构**：一级类别下挂二级类别；二级类别必须指定父类别。
  3. **挂有商品的类别不应能直接删除**：须先移除商品或改挂到其他类别（BR-11）。
  4. 系统**不应提供**"移动类别归属 / 换父类别"的操作（EX-05）。
- **验收标准**：
  1. 可新建一级类别，并在其下新建二级类别。
  2. 对含有商品的类别执行删除时，操作被拒绝并给出提示。
  3. 将某类别下商品全部改挂或下架后，该类别可被删除。
  4. 界面中不存在"移动类别 / 更换父类别"的操作入口。

#### FR-S-04 发布商品

- **前置条件**：已登录卖家；已存在至少一个二级类别。
- **规则**：
  1. **必填项**：商品名称、商品价格、所属类别（**必须挂到二级类别**）、库存数量（**≥ 1**，BR-05）。
  2. **选填项**：商品描述（富媒体）、商品图片（至多 9 张，JPG/PNG，单张 ≤ 5MB，BR-18）。
  3. 商品价格应 **> 0 且 ≤ 9,999,999.99 元**，两位小数，人民币（BR-26）。
  4. 商品名称长度上限 128 字符（T-33）。
  5. 发布成功后商品进入**在售**状态。
  6. 发布后**名称、价格、描述、图片不可修改**（BR-29、EX-03）。
  7. 上传不合规（超张数、格式不符、单张超限）时应**即时校验并拒绝**，给出字段级提示，**不应静默丢弃**（T-23）。
- **验收标准**：
  1. 未挂到二级类别时发布被拒绝。
  2. 库存填 0 或负数时发布被拒绝。
  3. 价格填 0、负数或超过 9,999,999.99 时发布被拒绝。
  4. 上传第 10 张图片、或上传 6MB 的 JPG、或上传 GIF 时，系统拒绝并提示，不静默丢弃。
  5. 不填描述、不传图片也可发布成功。
  6. 发布成功的商品立即出现在买家端列表与搜索结果中。
  7. 发布成功后，该商品的名称、价格、描述、图片均无编辑入口。

#### FR-S-05 编辑商品

- **前置条件**：已登录卖家；目标商品存在。
- **规则**：
  1. 可编辑字段**仅两项**：**库存数量**（可手动调高或调低）、**所属类别（改挂到其他二级类别）**。
  2. 名称、价格、描述、图片**发布后无编辑功能**；如需变更，路径是**手动下架后重新发布**。
  3. 将库存调至 **0** 时，商品应**自动下架**（售罄），与成交扣减至 0 的处理一致（T-31）。
- **验收标准**：
  1. 可将某在售商品的库存由 3 改为 5，商品保持在售。
  2. 可将某在售商品改挂到另一二级类别，买家端按新类别可见。
  3. 商品编辑界面中不存在名称、价格、描述、图片的编辑控件。
  4. 将库存由 1 改为 0 时，商品立即变为已下架（售罄），且买家端不可见。

#### FR-S-06 手动下架

- **前置条件**：已登录卖家；目标商品处于**在售**或**已冻结**状态。
- **规则**：
  1. 卖家**可随时**在后台对商品执行手动下架（BR-21）；库存已为 0 的商品由系统自动下架，无需手动。
  2. **交易进行中（已冻结）的商品也允许手动下架**（BR-38）。
  3. 下架后买家端**立即不可见、不可打开详情、不可提交意向**。
  4. 下架后，本次交易中的意向与队列中未成交的意向，**沿用交易失败的处置规则**：作废或重新排队，由**卖家**决定（BR-34、BR-38）。
  5. 手动下架的商品**不应进入历史商品列表**（BR-32、BR-33）。
  6. 手动下架的商品**无重新上架路径**（EX-14）。
- **验收标准**：
  1. 对在售商品执行手动下架后，买家端列表、搜索结果中均检索不到该商品，详情 URL 不可访问。
  2. 对已冻结商品执行手动下架时，操作**不被阻止**。
  3. 手动下架后，卖家在处理界面被要求对未终结意向选择"作废"或"重新排队"。
  4. 手动下架的商品不出现在"历史商品"列表中。
  5. 该商品在卖家后台不存在"上架 / 重新上架"按钮。

#### FR-S-06b 不提供的商品操作（约束性条款）

系统**不应**向卖家提供以下操作：

1. **删除商品**：任何状态下都不能删，退出销售只能走三种下架（BR-28、EX-12）。
2. **手动冻结 / 手动解冻**（BR-27、EX-13）。
3. **手动上架**：需求只定义了"库存归零的售罄，补货后重新上架"，未定义"把手动下架的商品重新上架"（BR-32、EX-14）。

- **验收标准**：卖家后台的商品操作区不出现删除、冻结、解冻、上架四类入口；通过直接访问相关 URL 也无法执行。

#### FR-S-07 补货与售罄重新上架（仅适用于"售罄"）

- **前置条件**：目标商品为**因库存归零且未成交**而售罄下架（BR-31）。交易成功导致的已售为终态，**不适用**本功能（BR-30）。
- **规则**：
  1. 卖家可在后台将该商品库存由 0 调为正数；调整后商品**仍为已下架**，**不会自动恢复在售**。
  2. 卖家须再执行**重新上架**操作，商品才回到在售。
  3. 重新上架后**重新收意向**；**原队列不恢复**，系统**不通知买家**（BR-09、EX-09）。
- **验收标准**：
  1. 将售罄商品库存由 0 改为 3 后，商品状态仍为已下架，买家端不可见。
  2. 执行重新上架后，商品回到在售，买家端可见、可下单。
  3. 重新上架后该商品的意向队列为空，售罄前排队的旧意向不再出现在队列中。
  4. 对"交易成功下架（已售）"的商品，**不提供**重新上架入口，即使将其库存调高也不回到在售。

#### FR-S-08 查看意向队列

- **前置条件**：已登录卖家。
- **规则**：
  1. 系统应按**商品维度**展示意向列表，条目至少包含：**位次、客户用户名、电话、提交时间、当前状态**。
  2. 商品被冻结期间**不接受新意向**，已排队意向保留。
  3. 位次按提交时间**实时计算**，实时展示。
- **验收标准**：
  1. 打开某商品意向队列，可见排队客户的位次、用户名、电话、提交时间与状态。
  2. 商品处于已冻结时，队列不再新增条目，原有条目完整保留。
  3. 新客户提交后，队列位次实时更新，新客户排在队尾。

#### FR-S-09 发起交易（并自动冻结）

- **前置条件**：已登录卖家；目标商品处于在售且有未终结意向。
- **规则**：
  1. 卖家**主动发起**交易，系统**强制取队首**（最早提交且未终结者），一次只对一人、只卖 1 件（BR-07）。
  2. 发起后该商品**自动冻结**，冻结期间停止接受新意向。
  3. **本版不提供手动冻结与手动解冻**（BR-27、EX-13）；卖家若想中止本次交易，只能**标记交易失败**（FR-S-11）。
  4. 冻结**只锁该件商品**，其他商品照常浏览与提交意向（BR-01）。
- **验收标准**：
  1. 发起交易时，被选中的客户**必然是队首**，卖家无法选择队列中其他位次的客户。
  2. 发起后该商品状态变为已冻结，买家端列表与搜索中检索不到。
  3. 商品冻结期间，其他商品的浏览与下单不受影响。
  4. 后台不存在独立的"冻结商品"或"解冻商品"按钮。

#### FR-S-10 标记交易成功

- **前置条件**：目标商品处于已冻结，存在进行中的交易。
- **规则**：
  1. 标记成功时，库存**减 1**（BR-02）。
  2. 减后库存 **> 0**：商品回到**在售**，可继续接受意向。
  3. 减后库存 **= 0**：商品进入**已下架（交易成功下架 / 已售）**，为**终态**，补货也不应使其重新上架，并**进入历史商品**（BR-30）。
  4. **不应允许超卖**：库存为 0 后不应继续成交（BR-03）。
  5. 该笔意向的交易结果记为**成功**，交易时间＝标记时间。
  6. 若同一客户在该商品上还有其他未终结意向，其余意向**一并作废**、记为失败（BR-35）。
- **验收标准**：
  1. 库存为 3 的商品成交一单后，库存变为 2，商品状态为在售，买家端可见。
  2. 库存为 1 的商品成交一单后，库存变为 0，商品状态为已下架（已售），买家端不可见。
  3. 已售商品即使被调高库存，也不会回到在售。
  4. 库存为 0 的商品不能再发起新的交易。
  5. 客户历史下单记录中该笔显示为"成功"。
  6. 同一客户在同一商品上的其余未终结意向同批变为"失败"。

#### FR-S-11 标记交易失败

- **前置条件**：目标商品处于已冻结，存在进行中的交易。
- **规则**：
  1. 商品**恢复在售**；本次意向作废还是重新排队由**卖家确认**，系统**不自动递补**下一位进入交易（BR-08）。
  2. 选择"作废"：该意向记为**失败**，进客户历史下单记录。
  3. 选择"重新排队"：旧记录以**失败**结案，生成一条新记录排至**队尾**、下单时间刷新为当前时间（BR-37、T-27）。
  4. 交易失败**不扣减库存**，因此不存在库存回滚问题（BR-02）。
  5. 该商品因曾发生交易失败，**应计入历史商品**（BR-33）。
- **验收标准**：
  1. 标记失败后商品状态变为在售，买家端可见、可下单。
  2. 标记失败后系统**不自动**让下一位进入交易，需卖家再次发起。
  3. 选择"作废"后，客户历史中该笔显示为"失败"。
  4. 选择"重新排队"后，该客户在队列中位于队尾，且下单时间为重新排队的时间。
  5. 标记失败前后该商品库存数字不变。
  6. 该商品出现在卖家后台的历史商品列表中。

#### FR-S-12 查看历史商品

- **前置条件**：已登录卖家。
- **规则**：
  1. **历史商品的定义**：不是"当前不在售"，而是"**有过交易结果或下架经历**"的记录（BR-33）。
  2. 应只列**三类来源**：
     - ① **已售商品**（交易成功下架）；
     - ② **交易失败商品**——交易失败后商品回到在售继续卖，**仍算历史商品**；
     - ③ **库存耗尽下架商品**（售罄）。
  3. **手动下架的商品不在其中**（BR-32）。
  4. **按商品维度只显示一条**，交易结果取该商品的最终结果（成功即为已售），历次明细通过该商品的意向名单查看（BR-36）。
  5. 商品下架不删历史；历史记录一旦产生即留存。
- **验收标准**：
  1. 一件经历过交易失败、当前仍在售的商品，出现在历史商品列表中。
  2. 一件被手动下架的商品，**不出现**在历史商品列表中。
  3. 一件已售商品与一件售罄商品均出现在列表中。
  4. 同一商品发生多次交易时，列表中只占一行，结果取最终结果。

#### FR-S-13 查看客户列表

- **前置条件**：已登录卖家。
- **规则**：
  1. 「全部客户」＝**系统中全部注册账号**，注册即入列，与是否下单无关；**不含未注册游客**（BR-22）。
  2. 每条展示：**用户名、电话、默认交易地点、注册时间**；**不应有"姓名"字段**（注册时未设）。
  3. 客户用户名**允许与卖家用户名相同**（两者为独立账号体系，T-35）。
  4. 电话**全量明文**可见（交易联系方式），约束仅为不得向第三方泄露。
  5. 应可**点进**某客户查看其购买历史（FR-S-14）。
  6. 不做：账号编辑 / 禁用 / 删除、导出、搜索与筛选（EX-06）。
- **验收标准**：
  1. 新注册但未下单的客户也出现在列表中。
  2. 列表字段为用户名、电话、默认交易地点、注册时间，无"姓名"列。
  3. 默认交易地点未填写的客户，该列显示"未设置"或空，不报错。
  4. 点击某客户可进入其购买历史页。
  5. 列表中不存在编辑、禁用、删除、导出、搜索、筛选入口。

#### FR-S-14 查看客户购买历史

- **前置条件**：已登录卖家；已选中某客户。
- **规则**：
  1. 只含**终态**记录（成功 + 失败）；排队中与交易中的意向**不应**出现，那部分走"按商品意向队列"查看（FR-S-08）。
  2. 每条字段：**商品名（快照）、下单时间、交易结果、交易时间**，与买家端对齐；**不应**包含价格、数量、地点。
- **验收标准**：
  1. 打开某客户购买历史，只看到成功与失败的记录。
  2. 字段为商品名、下单时间、交易结果、交易时间四项，无价格、数量、地点。
  3. 与 FR-C-07 中该客户自己看到的记录集合一致。

## 4. 业务规则

> 本章规则为**跨功能的强制性约束**。凡与第 3 章描述冲突之处，以本章为准。依据列中【已裁定】表示需求方已给出确定结论，**可作为验收依据**。

### 4.1 商品与库存

| 编号 | 规则 | 依据 |
|---|---|---|
| BR-01 | 同时在售商品数量**无上限**；每件商品独立排队、独立冻结 | 【已裁定】 |

## 5. 状态与流转

### 5.1 商品状态

商品有**三个状态**：**在售、已冻结、已下架**。

| 状态 | 含义 | 进入方式 | 买家端可见 | 可提交意向 |
|---|---|---|---|---|
| 在售 | 正常售卖 | 发布（库存 ≥1）；成交后库存减 1 仍有余量；售罄后补货并重新上架 | 列表、搜索、详情均可 | 是 |
| 已冻结 | 卖家正与队首客户交易 | **仅**由卖家对该商品发起交易（自动冻结） | **不在**列表与搜索中；仅可直链打开只读详情 | 否 |
| 已下架 | 退出销售 | 见 5.2 三种成因 | 完全不可见，详情也打不开 | 否 |

### 5.2 已下架的三种情形

| 情形 | 触发 | 含义 | 可恢复性 | 进历史商品 |
|---|---|---|---|---|
| ① 交易成功下架（**已售**） | 卖出最后一件，库存由 1 减到 0 | 与基线"交易成功撤下"同义 | **终态，不可恢复**；补货也不重新上架 | **是** |
| ② 库存为 0 自动下架（**售罄**） | 库存归零但**没有成交**（如卖家把库存调到 0） | 售罄 | **可恢复**：补货后**重新上架** | **是** |
| ③ 卖家手动下架 | 卖家在后台**随时**主动操作（**交易中也可**） | 已下架 | **无重新上架路径**（EX-14） | **否** |

> **关键区分**：① 与 ② **不是同一个状态**。只有"库存归零但没成交"才算售罄、可补货恢复；"卖出最后一件成交了"是**已售终态**。

### 5.3 商品状态转移表

| 当前状态 | 事件 | 下一状态 | 说明 |
|---|---|---|---|
| （无） | 卖家发布（库存 ≥1） | 在售 | 名称、价格、类别、库存必填 |
| 在售 | 卖家发起交易（取队首） | 已冻结 | 只锁该件商品，其他商品不受影响 |
| 已冻结 | 标记交易成功，库存 −1 后 **> 0** | 在售 | 纠正旧口径："成交即下架"只在卖出最后一件时成立 |
| 已冻结 | 标记交易成功，库存 −1 后 **= 0** | 已下架（交易成功下架 / **已售**） | 终态，进历史商品 |
| 已冻结 | 标记交易成功，库存 −1 后 **< 0** | **不允许** | 超卖不允许 |
| 已冻结 | 标记交易失败 | 在售 | 作废或重新排队由卖家确认（BR-08） |
| 在售 | 卖家手动下架 | 已下架 | 可随时操作（BR-21） |
| 已冻结 | 卖家手动下架 | 已下架 | 交易中也可；未终结意向按 BR-38 处置 |
| 在售 | 库存被调至 0（非成交） | 已下架（售罄） | 进历史商品 |
| 已下架（售罄，库存 = 0） | 卖家调高库存 | **仍为已下架** | 不自动恢复在售，须再执行重新上架 |
| 已下架（售罄） | 卖家重新上架 | 在售 | 仅售罄情形可恢复（FR-S-07） |

**状态机不变式（任何时刻必须成立）**

- INV-1：冻结**只由发起交易自动触发**；不存在手动冻结与手动解冻。
- INV-2：冻结**不占库存**，排队**不占库存名额**；库存只在成交那一刻减 1。
- INV-3：状态切换与库存扣减必须一致，**任何情况下库存不应为负**。
- INV-4：**商品不可删除**，任何状态下都无删除入口。
- INV-5：手动下架的商品**无重新上架路径**。

### 5.4 下单记录（意向）状态与结局

| 状态 | 含义 | 进入方式 | 进历史下单记录 |
|---|---|---|---|
| 排队中 | 已提交，等待被发起交易 | 客户提交意向 | 否 |
| 交易中 | 卖家已发起交易，等待标记结果 | 卖家发起交易（该意向为队首） | 否 |
| 已终结 | 已有明确结果 | 标记成功 / 标记失败 / 下架导致作废 | **是** |

**结局（终态）只有两档**：**成功、失败**。本版**不存在"撤销"终态**（客户无撤销入口）。

| 结局 | 产生方式 |
|---|---|
| 成功 | 卖家标记交易成功（FR-S-10） |
| 失败 | 卖家标记交易失败并选择作废（FR-S-11）；选择重新排队时旧记录结案（BR-37）；商品下架导致作废（BR-34）；同客户同商品成交后其余意向作废（BR-35） |

## 附录 A · 原始需求原文

**基线需求（R-1）**

最简单而又可用的在线购物系统（MVP），具备功能如下：

1. 只卖一个商品，卖掉一个，再制作一个，再卖。
2. 只有一个卖家。
3. 没有用户注册，当查看后想要购买时，再填入用户信息。
4. 线下交易，一手交钱一手交货。
5. 在实施线下交易前，商品暂且冻结，直到交易成功，把商品撤下，或者交易失败，商品恢复上线。
6. 卖家有一个后台，用于发布一个商品、查看历史商品、查看意向购买人信息、冻结商品等功能。
7. 卖家可修改密码。
8. 其中商品信息包括：商品名称、商品描述、商品图片、商品价格。
9. 附加要求：根据基线需求完善成正常正确的需求，不自行多加需求。

**升级包 A.1 · 商品管理升级（R-2）**

- 可以同时发布多个商品
- 商品支持 2 级类别管理
- 每种商品具有库存数量，当库存数量为 0 时，商品自动下架
- 商品可以通过浏览和搜索两种方式被用户查找到
- 商品图片可以多张，商品描述支持富媒体

**升级包 A.2 · 客户升级（R-3）**

- 允许客户自由注册，包括用户名、密码、电话、默认交易地点
- 客户登录后可以查看历史下单记录
- 商家可以查看所有注册的客户信息，以及他们的购买历史

## 附录 B · 教辅已确认口径（2026-10-22）

1. 浏览商品、查看详情免登录；**提交购买意向必须注册登录**。
2. **口令码整套废除**，账号取代（买家凭账号认领意向、查下单记录）。
3. 库存在**卖家标记「交易成功」那一刻**扣减。
4. **售罄下架 ≠ 成交下架**：售罄可补货后恢复；成交下架为终态不可恢复。
5. 多库存仍**先到先得排队**，一次只对队首一人，成交一单减 1 轮到下一个。
6. **富媒体 = 富文本 + 内嵌图片 + 内嵌视频**，不支持外部链接。

> 说明：第 3、4 条已由需求方后续裁定细化——成交后库存 > 0 时商品回到在售，"成交即下架"只在卖出最后一件时成立；第 6 条的视频部分本轮列为待确认（T-4）。
