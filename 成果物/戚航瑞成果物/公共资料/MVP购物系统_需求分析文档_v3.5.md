## 1. 引言

### 1.1 编写目的

依据基线需求、升级包 A 以及需求方对全部澄清问题的答复，形成完整、无歧义的需求描述，明确角色、功能、业务规则、数据定义与状态流转，作为需求规格说明书、设计与验收的依据。

### 1.2 项目范围

本系统是一个**可同时发布多件商品**的极简在线购物系统，服务于**一名卖家**与**注册客户**：

- 卖家在后台发布商品、维护二级类别与库存、按先来后到与买家线下交易、查看客户与历史。
- 客户注册后登录，浏览或搜索商品，对商品提交购买意向（即下单），并查看自己的历史下单记录。
- 交易在线下完成（一手交钱一手交货），系统不涉及在线支付与物流。

**本版本明确不做的功能**（详见第 8 章）：手动下架以外的商品编辑、客户自助修改资料、账号注销、历史记录删除、数据导出、全站订单总览等。

### 1.3 术语定义

| 术语 | 定义 |
|---|---|
| 在售 | 商品可被浏览、搜索、提交意向的状态 |
| 已冻结 | 卖家正与队首买家交易中，该商品停止接受新意向；**仅锁该件商品，不影响其他商品**。本版**由发起交易自动触发**，不提供手动冻结 |
| 已下架 | 商品退出买家端的状态，有三种成因：售罄自动下架、手动下架、卖出最后一件成交下架 |
| 售罄 | 库存减至 0 触发的自动下架；补货后可由卖家手动重新上架 |
| 手动下架 | 卖家主动将在售商品撤下的操作；库存 > 0 时可再手动上架 |
| 意向 / 下单记录 | 客户提交购买意向即生成一条下单记录（下单时间＝提交时间），交易结果后续更新为成功/失败 |
| 队首 | 同一商品队列中最早提交且未终结的意向；卖家发起交易时强制取队首 |
| 主图 | 该商品**第一张**上传的图片，用于列表与搜索结果展示；无图片时显示占位图 |
| 富媒体 | 商品描述支持富文本格式与内嵌图片（视频见第 9 章待确认项） |
| 默认交易地点 | 客户注册时选填的线下交割地点，供交易联系使用 |

## 2. 用户角色

| 角色 | 说明 |
|---|---|
| 游客 | 未注册未登录。**可浏览、可搜索**，但**不能提交购买意向**——提交意向必须注册登录 |
| 注册客户 | 注册后凭**用户名 + 密码**登录。提交购买意向（下单）、查看自己的历史下单记录 |
| 卖家 | 系统唯一管理用户，凭用户名 + 密码登录后台，完成全部商品、类别、库存、交易与客户管理 |

> 需求方已明确：注册字段是**用户名**（不是姓名）；客户**不能自助修改资料**、**不能注销账号**。

## 3. 核心业务模型

### 3.1 商品状态机

商品有三个状态：**在售、已冻结、已下架**。

| 状态 | 含义 | 进入方式 | 买家端可见 | 可提交意向 |
|---|---|---|---|---|
| 在售 | 正常售卖 | 发布（库存 ≥1）；成交后库存减 1 仍有余量；售罄后补货并手动上架 | 列表、搜索、详情均可 | 是 |
| 已冻结 | 卖家正与队首交易 | **仅**卖家对该商品发起交易（**自动冻结**） | **不在浏览列表与搜索结果中**；仅可通过直链打开详情（只读） | 否 |
| 已下架 | 退出销售 | 见下表三种成因 | 完全不可见，**详情也打不开** | 否 |

**已下架的三种情形**（需求方 2026-10-26 明确：只有这三种，且**商品不可直接删除，只能下架**）

| 情形 | 触发 | 状态含义 | 可恢复性 | 是否进历史商品 |
|---|---|---|---|---|
| ① **交易成功下架（已售）** | 卖出最后一件、库存从 1 减到 0 | 与基线"交易成功撤下"同义 | **终态，不可恢复**——补货也不会让它重新上架 | **是** |
| ② **库存为 0 自动下架（售罄）** | 库存归零但**没有成交**（如卖家把库存调到 0） | 售罄 | **可恢复**：补货（调高库存）后**重新上架** | **是** |
| ③ **卖家手动下架** | 卖家在后台**随时**主动操作（**交易中也可**） | 已下架 | **需求未定义"手动上架"操作** → 本轮视为不可恢复 | **否** |

> 关键区分：① 与 ② **不是同一个状态**。只有"库存归零但没成交"才算售罄、能补货恢复；"卖出最后一件成交了"是**已售终态**。
> 历史商品**不是**"当前不在售"的判断，而是"有过交易结果或下架经历"的记录，只列三类来源（见 FR-S-12）。

**状态转移**

| 当前 | 事件 | 下一状态 | 说明 |
|---|---|---|---|
| （无） | 卖家发布（库存 ≥1） | 在售 | 名称、价格、类别、库存必填 |
| 在售 | 卖家发起交易（取队首） | 已冻结 | 冻结只锁该件商品，其他商品不受影响 |
| 已冻结 | 标记交易成功，库存 −1 后 **>0** | **在售** | 纠正旧口径："成交即下架"只在卖出最后一件时成立 |
| 已冻结 | 标记交易成功，库存 −1 后 **=0** | 已下架（**交易成功下架 / 已售**） | **终态，不可恢复**；进历史商品 |
| 已冻结 | 标记交易成功，库存 −1 后 **<0** | 不允许 | **超卖不允许** |
| 已冻结 | 标记交易失败 | 在售 | 该单作废或重新排队由**卖家确认**，不再自动递补；**这是卖家中止本次交易的明确途径**（无手动解冻） |
| 在售 | 卖家手动下架 | 已下架 | 卖家可**随时**在后台操作 |
| 已冻结 | 卖家手动下架 | 已下架 | 交易中也能下架；本次交易与队列未成交意向由卖家决定作废或重新排队（BR-38） |
| 在售 | 库存被调至 0（非成交） | 已下架（**售罄**） | 进历史商品 |
| 已下架（售罄，库存 = 0） | 卖家调高库存 | 仍为已下架 | **不会自动恢复在售**，须卖家**重新上架** |
| 已下架（售罄） | 卖家重新上架 | 在售 | 仅售罄情形可恢复，无需重新发布 |

- 冻结**只由发起交易自动触发**，本版**不提供手动冻结，也不提供手动解冻**。
- 冻结**不占库存**，排队也不占库存名额；库存只在成交那一刻减 1。
- 状态切换与库存扣减必须一致，**任何情况下不得超卖**。
- **商品不可删除**：任何状态下都没有删除入口，退出销售只能走三种下架。
- **本轮不提供"手动上架"操作**：需求方明确只有"库存归零的售罄，补货后能重新上架"，手动下架的商品无重新上架路径（见 BR-32、EX-14）。

### 3.2 多商品与独立队列

- 同时在售数量**没有上限**，不设数量封顶。
- **每件商品各自一条意向队列**，冻结按单件商品单独走；一件冻结不影响其他商品。
- 冻结一件商品时，其他商品照常浏览、照常提交意向。
- 卖家能否同时与多个商品的队首并行交易：**待确认**（见第 9 章 T-2）。

### 3.3 库存模型

- 库存数量：**非负整数**；**发布时要求 ≥ 1**（需求方纠正：填 0 会直接下架、卖家自己都看不见，别扭）。
- 库存**上限未规定**。
- 扣减时机：**卖家标记「交易成功」那一刻减 1**；提交意向不预占、不扣减。交易失败本来就没扣，因此不存在回滚问题。
- 每单**固定 1 件**，一次只卖 1 件，不允许一次买多件。库存数量含义是"这件商品备了几件、可以卖几单"。
- **库存不限制排队人数**：库存 3 也允许超过 3 人排队，第 4 个买家照常排队、照常看到商品；只有库存归零、商品下架后才停止收新意向。
- 补货：后台手动把库存调上去；补货后**须卖家手动重新上架**，不重新发布新品；**原队列不恢复**，系统不通知买家（买家自己刷新看到重新上架才知道）。

### 3.4 意向队列与先到先得

- 交易对象严格**先来后到**：卖家发起交易时**强制取队首**，不能跳选。
- 成交或终结后，队列自动前移，下一位成为新队首继续排队；但**不会自动冻结成交**——每笔交易都由卖家主动发起。
- **失败自动递补已取消**：交易失败即商品恢复在售，该单作废还是重新排队由卖家在后台确认，不是自动递补。
- 同一账号对同一商品重复提交：**不做去重**，就是多条独立意向记录，按提交时间排队、先到先得（按账号识别，不按手机号——手机号本就不唯一）。
- 同一客户能否同时排多件商品的队：**待确认**（见 T-1）。

### 3.5 下单记录与历史

- **提交购买意向即视为"下单"**，那一刻生成记录（下单时间＝提交时间），交易结果后续更新为**成功 / 失败**。
- 客户**没有主动撤销意向的动作**；"撤销"这一终态在本版不存在。
- 历史只含**终态记录**（成功、失败）；排队中、交易中的意向**不进历史**。
- 买家端是否提供"进行中意向"的跟进入口：**待确认**，临时边界为不展示（见 T-3）。
- 历史**只读、不可删除**；商品下架不影响已有记录展示，商品名显示**下单时的快照**。
- **下架导致的未成交意向**按交易失败规则处置：作废或重新排队由卖家确认，作废即记为"失败"（见 BR-34）。
- **同一客户对同一商品的多条意向**，成交其一后其余一并作废、记为"失败"（见 BR-35）。
- **历史商品按商品维度只显示一条**，结果取最终交易结果；历次明细看该商品的意向名单（见 BR-36）。

### 3.6 类别模型

- **二级类别树**：一级 → 二级，商品**必须挂到二级类别**才能发布，不允许"不选类别"的商品存在。
- 类别由**卖家在后台维护**：新增、重命名、删除；**不能移动类别归属**（无"大类移到别的大类下"操作）。
- **挂着商品的类别不能直接删**：必须先移除商品或改挂到其他类别。
- 已发布商品的类别可通过两种方式变化：类别重命名（商品显示跟新名字走）、商品改挂到其他类别。
- 买家端支持**按二级类别筛选浏览**（本轮要做）。

### 3.7 商品图片与富媒体

- 图片**至多 9 张**，格式仅 **JPG/PNG**，单张 **≤ 5MB**；**选填**（可一张不传）。
- **主图 = 第一张上传的图片**，不用单设封面字段；一张都没传时，列表 / 搜索 / 详情统一显示**占位图**。
- 详情页需能查看**全部**商品图（至少可按序逐张看完）。
- 图片调序、单独删除、单独指定主图：**本轮不做**（依赖编辑商品，而本轮唯一可调的是库存）。
- 描述**选填**，支持富媒体：富文本基础格式（段落、加粗、斜体、列表）+ 内嵌图片；**禁止脚本、交互控件、复杂表格、公式**。视频内嵌见第 9 章 T-4。
- 描述插图与商品图**分开计数**，插图不计入 9 张名额。

## 4. 功能需求

### 4.1 客户侧

**FR-C-01 浏览商品**

- **免登录**可用。默认列表**只含在售商品**；已冻结商品不在列表与搜索结果中。
- 列表卡片展示：**商品名称、价格、主图、所属类别**；**不展示描述**，也不展示库存状态（库存只在详情页展示）。
- 支持按二级类别筛选；排序按发布时间。
- 分页与每页条数：**待确认**（见 T-5）。

**FR-C-02 搜索商品**

- **免登录**可用。匹配字段：**商品名称 + 描述**（先剥标签、按纯文本匹配）；**类别不参与搜索**。
- 结果只含**在售商品**；结果字段：名称、价格、主图、所属类别。
- 模糊/精确、大小写、结果排序、空关键词与无结果提示：**待确认**（见 T-6 ~ T-8）。

**FR-C-03 查看商品详情**

- 在售商品：可看名称、价格、富媒体描述、**全部商品图**、所属类别、**库存状态**。
- 已冻结商品：**不在列表与搜索结果中**，唯一合法入口是**直链**（详情页 URL、分享链接）；打开后**只读**——能看全部图，但**不能买、不能提交意向**。
- 已下架（含售罄）商品：买家端**打不开详情**、不能提交意向，已从买家端彻底退出。

**FR-C-04 注册**

- 必填：**用户名、密码、电话**；**默认交易地点选填**。
- 密码：**不少于 8 位**（与卖家密码要求一致）；复杂度要求待确认（见 T-9）。
- **用户名必须唯一**，注册时校验、不允许重复。
- **电话不唯一**，一个手机号可注册多个账号；**无验证码**环节。
- 用户名长度与字符范围、电话位数格式：**待确认**（见 T-10、T-11）。
- 注册后自动登录、会话时长、退出登录：**待确认**（见 T-12）。

**FR-C-05 登录**

- 用**用户名**登录（用户名是唯一标识）；电话只用于交易联系，**不作登录凭证**。
- 登录失败提示、失败次数限制、锁定：**待确认**（见 T-13）。

**FR-C-06 提交购买意向（下单）**

- **必须注册并登录**；未登录点「我要购买」引导至注册/登录页。未登录用户**没有任何提交意向的通道**——原口令码入口随机制一起废除，不再出现在界面。
- 一单**固定 1 件**；提交成功即生成一条下单记录（挂在客户账号下）。
- 意向信息**直接取自账号**（用户名、电话），客户**没有"修改意向信息"的入口**。

**FR-C-07 查看历史下单记录**

- 登录后可用；只展示**已有明确交易结果（成功 / 失败）**的记录。
- 每条至少展示：**商品名称（快照）、下单时间、交易结果、交易时间**；不含价格、图片、排队位次，也看不到同队列其他买家的信息。
- **按时间倒序**排列，**支持翻页**。
- **只读、不可删除**；商品下架后仍照常可看，商品名显示下单时的快照。
- 单条详情页、筛选/搜索、每页条数：**待确认**（见 T-14 ~ T-16）。

**FR-C-08 不提供的客户侧能力**

- **不能修改个人资料**（用户名、电话、默认交易地点注册后都不可改；改密码只卖家有）。
- **不能撤销意向**。
- **不能注销账号**。

### 4.2 卖家后台

**FR-S-01 登录 / FR-S-02 修改密码**

- 凭用户名 + 密码登录；未登录不得访问后台。
- 修改密码须**先验证原密码**；新密码不少于 8 位。

**FR-S-03 类别管理**

- 可对类别**新增、重命名、删除**。
- **有商品的类别不能直接删**：须先移除商品或改挂到其他类别。
- **不提供**"移动类别 / 换归属"操作。

**FR-S-04 发布商品**

- 必填：**名称、价格、类别（须挂到二级）、库存数量（≥ 1）**。
- 选填：**描述**（富媒体）、**图片**（至多 9 张，JPG/PNG，单张 ≤ 5MB）。
- 发布后**名称、价格、描述、图片不可修改**。

**FR-S-05 编辑商品**

- 可编辑两项：**库存数量**（可手动调整）、**所属类别（改挂）**。
- 名称、价格、描述、图片**发布后没有编辑功能，就是固定的**；若要改，路径是**手动下架 → 重新发布**。

**FR-S-06 手动下架**

- 卖家**想下架随时能在后台手动操作**（库存 = 0 已自动下架，无需手动）。
- 下架后买家端**立即不可见、不可开详情、不可提交意向**。
- 手动下架的商品**不进入历史商品列表**（历史商品只列已售、交易失败、库存耗尽三类）。
- 手动下架后**队内未成交意向的处理**：待确认，临时边界＝**作废**（见 T-17）。
- **交易进行中（已冻结）时也可以手动下架**：下架后，本次交易中的意向与队列里未成交的意向，由卖家决定作废或重新排队（见 BR-38）。
- **本轮不提供"手动上架"**：手动下架的商品无重新上架路径（见 EX-14）。

**FR-S-06b 不提供的商品操作**

- **不提供删除商品**：任何状态下都不能删，退出销售只能走三种下架。
- **不提供手动冻结 / 手动解冻**（见 FR-S-09）。
- **不提供手动上架**：需求里只定义了"库存归零的售罄，补货后能重新上架"，没有"把手动下架的商品重新上架"这个操作（见 EX-14）。

**FR-S-07 补货与重新上架（仅适用于"售罄"）**

- 前提：该商品是因**库存归零且未成交**而售罄下架的（交易成功导致的已售为终态，不适用）。
- 后台手动把库存从 0 调成正数；改后商品**仍是已下架**，须卖家**再重新上架**。
- 补货重新上架后**重新收意向**，**原队列不恢复**；系统**不通知买家**。

**FR-S-08 查看意向队列**

- 按商品维度展示意向列表：位次、客户用户名、电话、提交时间、状态。
- 商品被冻结期间不接受新意向，已排队意向保留。

**FR-S-09 发起交易（并自动冻结）**

- 卖家主动发起，**强制取队首**（最早提交且未终结者），一次只对一人、只卖 1 件。
- 发起后该商品**自动冻结**，冻结期间停止接受新意向。
- **本版不再提供手动冻结与手动解冻**：冻结只由本操作触发。卖家若想中止本次交易，只能**标记交易失败**（FR-S-11）。

**FR-S-10 标记交易成功**

- 库存**减 1**；减后 > 0 则商品回到**在售**，= 0 则**已下架（售罄）**。
- 不得超卖：库存为 0 后不再继续成交。

**FR-S-11 标记交易失败**

- 商品**恢复在售**；该单作废还是重新排队由**卖家确认**，**不自动递补**下一位进入交易。

**FR-S-12 查看历史商品**

- **历史商品是什么**：不是"当前不在售"的状态判断，而是"**有过交易结果或下架经历**"的记录。
- 只列**三类来源**：
  1. **已售商品**（交易成功下架）
  2. **交易失败商品**——注意：交易失败后商品会回到"在售"继续卖，**它仍然算历史商品**（因为曾发生交易失败）
  3. **库存耗尽下架商品**（售罄）
- **手动下架的商品不在其中**（不在三类来源内）。
- 商品下架不删历史；历史记录一旦产生就留存。

**FR-S-13 查看客户列表**

- 「全部客户」= **系统中全部注册账号**，注册即入列，与是否下单无关；不含未注册游客。
- 每条展示：**用户名、电话、默认交易地点、注册时间**；**没有"姓名"字段**（注册时就没设）。
- 电话**全量明文**可见（是交易联系方式），约束仅为"不得向第三方泄露"。
- 可**点进**某客户查看其购买历史。
- 不做：账号编辑 / 禁用 / 删除、导出、搜索与筛选。

**FR-S-14 查看客户购买历史**

- 只含**终态**（成功 + 失败）；排队中 / 交易中的意向走"按商品意向队列"查看，不进购买历史。
- 每条字段：**商品名（快照）、下单时间、交易结果、交易时间**，与买家端对齐；不含价格、数量、地点。

## 7. 非功能需求

- **性能**：多商品、多客户规模下的常规浏览与操作响应应可接受；具体指标未由需求方规定。
- **安全**：密码加密存储，任何位置不出现明文；客户电话仅用于交易联系，不得向第三方泄露；富媒体描述禁止脚本与交互控件。
- **一致性**：商品状态切换与库存扣减必须一致，**任何情况下不得超卖**。
- **可靠性**：全部数据持久保存；发布、冻结、标记结果、改密等关键操作记录时间戳。
- **可用性**：游客可完成浏览与搜索；注册客户可完成"注册 → 登录 → 下单 → 查历史"全流程。

## 附录 A · 原始需求原文

**基线需求**

最简单而又可用的在线购物系统（MVP），具备功能如下：

1. 只卖一个商品，卖掉一个，再制作一个，再卖。
2. 只有一个卖家。
3. 没有用户注册，当查看后想要购买时，再填入用户信息。
4. 线下交易，一手交钱一手交货。
5. 在实施线下交易前，商品暂且冻结，直到交易成功，把商品撤下，或者交易失败，商品恢复上线。
6. 卖家有一个后台，用于发布一个商品、查看历史商品、查看意向购买人信息、冻结商品等功能。
7. 卖家可修改密码。
8. 其中商品信息包括：商品名称、商品描述、商品图片、商品价格。
9. 附加要求：根据基线需求完善成正常正确的需求，不自行多加需求。

**升级包 A.1 · 商品管理升级**

- 可以同时发布多个商品
- 商品支持 2 级类别管理
- 每种商品具有库存数量，当库存数量为 0 时，商品自动下架
- 商品可以通过浏览和搜索两种方式被用户查找到
- 商品图片可以多张，商品描述支持富媒体

**升级包 A.2 · 客户升级**

- 允许客户自由注册，包括用户名、密码、电话、默认交易地点
- 客户登录后可以查看历史下单记录
- 商家可以查看所有注册的客户信息，以及他们的购买历史

## 附录 B · 教辅已确认口径（2026-10-22）

1. 浏览商品、查看详情免登录；**提交购买意向必须注册登录**。
2. **口令码整套废除**，账号取代（买家凭账号认领意向、查下单记录）。
3. 库存在**卖家标记「交易成功」那一刻**扣减。
4. **售罄下架 ≠ 成交下架**：售罄可补货后恢复；成交下架为终态不可恢复。
5. 多库存仍**先到先得排队**，一次只对队首一人，成交一单减 1 轮到下一个。
6. **富媒体 = 富文本 + 内嵌图片 + 内嵌视频**，不支持外部链接。

> 说明：本版第 3.1 节按需求方后续裁定进一步细化——成交后库存 > 0 时商品回到在售，"成交即下架"只在卖出最后一件时成立；第 6 条的视频部分本轮列为待确认（T-4）。
