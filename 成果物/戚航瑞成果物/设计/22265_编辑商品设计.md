# 编辑商品设计

设计任务 #22265，开发任务 #22266。需求依据：FR-S-05、BR-29、BR-30、BR-31、BR-34、NFR-5。

## 交互与接口

旧版没有多商品库存与类别编辑。新版商品管理表格每行提供编辑按钮，弹窗仅包含“库存数量”和“所属二级类别”。商品名称只读提示，价格、描述和图片没有编辑控件。

`PATCH /api/admin/products/{id}`：JSON 必须恰含 `stock`、`categoryId`、`version`。版本号由后台详情接口返回，用于拒绝陈旧窗口覆盖新修改。服务端拒绝任何其他字段，以及小数、负库存、非二级类别。成功返回更新后的完整商品；陈旧版本返回 409。

## 状态一致性

| 修改 | 处理 |
| --- | --- |
| 在售库存 3 改为 5 | 保持在售 |
| 类别改挂 | 下一次买家查询按新类别可见 |
| 在售库存改为 0 | 同一事务切换为 depleted（售罄下架），详情返回 404 |
| 售罄后补到正数 | 仍保持 depleted，重新上架由 FR-S-07 模块接入 |
| 已售或手动下架后增加库存 | 保留终态/下架状态，不自动上架 |

使用 JPA `@Version` 和覆盖提交的写锁控制库存更新。当前为 SQLite 单实例部署设计，跨实例写入需要数据库层锁策略。

## 交易联调边界

如果商品已有 `tradingIntentId`，调零库存会影响正在交易和排队的意向。当前返回 409，要求先完成交易及意向处置，防止跳过 BR-34 的卖家决定。**这部分尚未与交易模块联调，不能视为“已实现交易中随时调零并处置全部意向”。**交易组员需在库存归零的同一事务接入逐条作废/重排，再开放该场景。没有绑定交易的冻结状态夹具可调零并进入售罄。
