# 开发交付说明

## 交付范围

覆盖列表、搜索、详情、二级类别、发布、库存/类别编辑 6 个商品模块。设计编号见本目录 README。任务信息来自用户粘贴的清单，未读取任务详情页的额外验收条件，未修改禅道状态。

## 数据约定

沿用 `product` 表，新增 `stock`（整数）、`category_id`、`description_text`（搜索纯文本）、`images_json`（按上传次序的 URL 数组）和 `version`。价格沿用 `price_cents`，新版校验上限为 999999999 分。`image` 仍保存第一张图，兼容已有静态图片读取方式。

新增 `category` 表。旧商品缺库存/类别时不进入新列表；不删除旧数据，也不猜测其分类和库存。旧数据迁移到新目录需团队另行确认。已有 SQLite 表由 Hibernate 补字段，版本列带默认值 0。

## 公开与后台接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/products | q/categoryId/page/size 查询在售商品 |
| GET | /api/products/{id} | 在售/冻结详情，下架返回 404 |
| GET | /api/categories | 公开两级类别树 |
| GET | /api/admin/products | 卖家商品管理分页 |
| GET | /api/admin/products/{id} | 卖家详情，含编辑 version |
| POST | /api/products | multipart 发布商品 |
| PATCH | /api/admin/products/{id} | JSON stock/categoryId/version |
| GET/POST | /api/admin/categories | 类别树/新增 |
| PATCH/DELETE | /api/admin/categories/{id} | 改名/删除 |
| POST | /api/admin/description-images | 描述图片上传 |
| POST | /api/auth/login / logout | 卖家会话 |

后台页面未登录跳转 `/login.html`；后台 API 未登录返回 401。会话存内存，重启失效。商品旧口令码、单商品查询、手动冻解与单商品交易接口统一返回 410，避免旧逻辑误操作新库存。旧版 `ShoppingService` 仍保留历史实现供代码参考，**不得在新模块调用其单商品/口令码/交易方法**。

## 联调边界与已知限制

1. 客户注册、客户登录、提交意向、队列与交易结果、客户与历史界面不在本次提供的任务清单内，未完成。详情目前只提示登录要求，没有可工作的客户登录或下单入口。
2. 真正交易绑定商品调零返回 409，需交易模块先接入 BR-34 的卖家逐条处置，不能跳过此边界。售罄重新上架和手动下架由相应模块实现，本次未增加相关按钮或接口。
3. 类别删除按 BR-11 阻止所有仍有关联商品的删除；FR-S-03 的“下架后可删”举例需课程组统一。
4. 描述插图暂沿用 JPG/PNG、单张 5MB 校验，不做视频。独立上传后放弃发布的图片不会自动清理。
5. 并发写锁面向当前 SQLite 单实例，多个应用实例需要数据库层协调。
6. 仓库根目录 `ShoppingSystemBlackBoxTest.java` 是旧单商品基线测试，尚不适用于新版；本次验证使用标准 `src/test` 新测试。

## 启动和验证

预装 JDK 17 后，在项目根目录执行：

```powershell
.\mvnw.cmd test
.\mvnw.cmd package
java -jar target\shopping-system-1.0.0.jar
```

默认买家页 `http://localhost:3000/`，后台 `http://localhost:3000/admin.html`。初始卖家账号沿用项目原有默认值，实际部署通过 `DEFAULT_SELLER_PASSWORD` 设置。

本次截图另用 3100（新版）与 3101（旧版）端口，数据库/上传均位于 `target/catalog-demo`、`target/catalog-before`，不使用正式 `data/shop.db`。截图展示的是演示记录。旧版来自修改开始前的 Git HEAD。两个版本同时登录时应分别使用 `127.0.0.1` 与 `localhost`，避免相同 host 的 cookie 在端口间覆盖。
