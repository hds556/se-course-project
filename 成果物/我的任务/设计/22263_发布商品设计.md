# 发布商品设计

设计任务 #22263，开发任务 #22264。需求依据：FR-S-04、BR-01、BR-05、BR-18～20、BR-26、T-23、T-39。

## 修改前后

旧版限制一件未售出商品，描述与单张图片必填。新版取消单商品限制，支持多个商品同时在售。必填：名称、价格、二级类别、库存。描述和图片可为空；第一张图片为主图，无图展示占位图。

## 发布流程

1. 卖家登录并建立二级类别。
2. 填名称、人民币价格、库存与类别；选填富文本描述和商品图。
3. 前端即时检查图片数、格式和大小，展示按选择顺序生成的预览。
4. 服务端再次校验全部字段和图片内容，净化描述，全部检查通过后写图片及商品。
5. 事务提交成功后返回商品详情，后台刷新，商品进入买家列表。

`POST /api/products` 使用 multipart/form-data：`name`、`price`、`stock`、`categoryId`、`description`，以及重复 `images` 文件字段。成功为 201；失败返回 error 和 fieldErrors，表单保留用户输入。

## 核心校验

| 字段 | 规则 |
| --- | --- |
| 名称 | 去首尾空白后非空，最多 128 个 Unicode 字符 |
| 价格 | >0 且 ≤9,999,999.99 元，最多两位小数，以整数分持久化 |
| 库存 | Java 整数，发布时 ≥1 |
| 类别 | 存在且必须为二级类别 |
| 商品图 | 0～9 张，JPG/PNG，单张 ≤5MB，校验扩展名、MIME 与实际解码格式 |
| 描述 | 服务端 HTML 白名单，删除脚本、事件、控件、表格和外部链接 |

描述插图单独通过 `POST /api/admin/description-images` 上传，不计入 9 张商品图。本实现为描述图沿用 JPG/PNG、5MB 校验，属于 T-18 的实现边界；视频未实现。只允许受控本地上传路径进入最终描述。

商品图先全部校验再写盘，事务回滚时删除本次已写文件。描述图上传独立提交，放弃发布时可能留下未引用文件，暂不自动清理，避免误删其他商品的引用。

## 验证与截图

覆盖价格上下界、非法数值、库存 0/负数/小数、缺少类别、9/10 张图、超限图、伪造 PNG、富文本净化、无图片发布。
