# 第四次迭代 · 商品状态机

负责人：谭梓良。需求依据为 [SRS V4.0](https://github.com/hds556/se-course-project/wiki/SRS) 的 FR-S-06、FR-S-07、FR-S-13 和 BR-26 至 BR-33。

| 需求 | 卖家如何操作 | 结果 |
| --- | --- | --- |
| #14206 调整库存 | 在「在售商品」调整可售数量，或在「历史商品」为售罄商品调整库存 | 改为 0 自动下架，售罄恢复正库存时自动回到在售。已有订单保持原状态 |
| #14213 手动下架 | 在售商品中选择「手动下架」并确认 | 从买家目录移除，进入历史。订单仍可推进或取消，取消回补后商品保持手动下架 |
| #14215 查看历史商品 | 在卖家工作台切到「历史商品」 | 查看当前已下架商品，按下架时间倒序，区分售罄与手动下架 |

库存、状态和下架时间在同一事务中写入。订单提交时扣到最后一件，和卖家直接把库存设为 0，都会记录售罄下架。买家或卖家取消订单时，库存按订单明细回补，只有售罄下架可以自动恢复。手动下架商品的历史视图为只读。对该商品提交有效库存调整时，库存可以更新，手动下架状态与时间保留，符合 SRS AC-07。

| 接口 | 说明 |
| --- | --- |
| `GET /api/admin/products` | 保留原分页结构，列出在售商品 |
| `PATCH /api/admin/products/{id}/stock` | 提交整数 `stock`，可同时传 `version` 防止覆盖新修改 |
| `POST /api/admin/products/{id}/withdraw` | 手动下架在售商品，可传 `version` |
| `GET /api/admin/products/offline` | 返回历史数组，包含 `offlineAt` 和 `offlineReason` |

历史成因由数据库状态编码确定。`depleted` 表示售罄，`withdrawn` 表示手动下架。下架时间保存在 `product.offline_at`。库存用 64 位整数存储，调整入口接受浏览器可精确表示的非负整数，订单回补不会发生 32 位溢出。

旧意向、冻结、单独补货和重新上架入口返回 HTTP 410。旧记录留存，启动时将旧商品状态转换成订单制可识别的状态。缺失或不可解析的旧下架时间按未知处理。

在仓库根目录运行 `mvnw.cmd test` 可执行全部测试。新增的 `ProductLifecycleIntegrationTest` 以 MockMvc、Spring Boot 与隔离 SQLite 验证状态转换、库存校验、权限、乐观版本校验及在途订单联动。
