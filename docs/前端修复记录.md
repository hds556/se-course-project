## 1. 修复背景

DEF-001 迭代中，超长价格（如 5000 位字符）提交后曾在后端 JSON 持久化阶段崩溃。当时的修复仅落在**后端**：Java 重构后服务端对金额做了长度/范围校验并返回 400，但**前端对价格、图片、密码等输入字段没有任何校验**，攻击输入依然可以完整提交到服务端。

按课程评审意见："输入字段检查要在前端里做好，并且在需求文档里说明"，本次修复将 SRS 中已定义的字段约束**前置到浏览器端**，形成"HTML 约束属性 + 提交前脚本检查 + 服务端最终校验"的三层防线。

## 2. 修复内容明细

### 2.1 卖家后台（`public/admin.html` / `public/admin.js`）

| 字段 | SRS 约束 | HTML 约束属性 | 提交前脚本校验（admin.js） |
|------|----------|---------------|---------------------------|
| 价格 | >0、最多两位小数、人民币元（FR-S-02 / BR-17） | `type="number" min="0.01" step="0.01" max="9999999.99"` | `validatePrice()`：正则 `^(0\|[1-9]\d{0,6})(\.\d{1,2})?$` + 数值范围检查，拦截超长/非法输入（DEF-001 场景在前端即被拒绝） |
| 商品图片 | JPG/PNG、≤5MB（FR-S-02 / BR-17） | `accept=".jpg,.jpeg,.png,image/jpeg,image/png"` | `validateImage()`：检查 MIME 类型与 `file.size ≤ 5MB` |
| 商品名称 | 发布后不可改（数据字典长度 128） | `maxlength="128"` | 依赖 HTML 约束 |
| 商品描述 | 同上（长度 2000） | `maxlength="2000"` | 依赖 HTML 约束 |
| 新密码 | ≥8 位且同时含字母和数字（FR-S-09 / BR-18） | `minlength="8"` + `pattern="(?=.*[A-Za-z])(?=.*\d).{8,}"` | `validatePassword()`：长度 + 字母/数字组合检查 |

### 2.2 买家侧（`public/index.html` / `public/app.js`）

| 字段 | SRS 约束 | 前端实现 |
|------|----------|----------|
| 姓名（提交意向 / 修改意向） | 必填、≤64 字符 | `required` + `maxlength="64"`（提交意向表单在 `app.js` 中渲染，同步修改） |
| 联系电话 | 必填、≤32 字符 | `required` + `type="tel"` + `maxlength="32"` |
| 口令码 | 8 位随机字母数字 | `maxlength="8"` + 提交前 `trim().toUpperCase()` 规范化（原有实现保留） |

说明：SRS 未规定电话号码格式，故仅做必填与长度限制，未自行增加格式校验（不超出需求基线）。

### 2.3 校验失败行为

- 校验不通过时在页面消息区即时提示具体原因，并将焦点移至出错字段，**请求不会发往服务端**。
- 服务端保留同一套约束的完整校验（防止绕过前端直连接口），是最终权威防线。

## 3. 修复前后对比（以 DEF-001 场景为例）

| 步骤 | 修复前 | 修复后 |
|------|--------|--------|
| 输入 5000 位价格 | 浏览器原样提交 | `type=number` 阻止输入，脚本校验二次拦截 |
| 提交发布请求 | 5000 位价格完整到达服务端 | 前端直接拒绝，无网络请求 |
| 服务端 | 返回 400（当时唯一的防线） | 兜底校验，正常流程不再触发 |

## 4. 验证方式建议

1. 发布表单输入超长价格（>5000 字符）、0、负数、三位小数——前端均应即时提示且无网络请求（浏览器开发者工具 Network 面板确认）。
2. 选择 >5MB 图片或非 JPG/PNG 文件——前端即时提示。
3. 新密码使用纯数字 8 位、7 位混合——前端即时提示。
4. 绕过前端（如用 curl 直连 `/api/products`）——服务端 400，约束仍然生效。
