# 数据库构建说明

> 本文档对应 `java_rebuild_v2` 分支（在 `java_rebuild` 分支基础上完成了数据库构建，关键提交：`943418e 完善数据库`，2026-10-12）。
> 讲解本版本如何选型、建表、初始化和迁移数据。

## 1. 数据库选型

| 项 | 选择 | 说明 |
|---|---|---|
| 数据库 | SQLite（单文件） | 免安装、免账号密码，拷走项目目录即可运行，适合课程项目与演示 |
| JDBC 驱动 | `org.xerial:sqlite-jdbc` | 见 `pom.xml` |
| Hibernate 方言 | `org.hibernate.community.dialect.SQLiteDialect` | 来自 `hibernate-community-dialects` 依赖 |
| ORM | Spring Data JPA + Hibernate 6 | 通过 `ddl-auto=update` 由实体类自动建表，**无需手写建表 SQL** |

连接配置见 `src/main/resources/application.properties`：

```properties
spring.datasource.url=jdbc:sqlite:${SHOP_DB_FILE:./data/shop.db}
spring.datasource.driver-class-name=org.sqlite.JDBC
spring.jpa.database-platform=org.hibernate.community.dialect.SQLiteDialect
spring.jpa.hibernate.ddl-auto=update
```

## 2. 数据库文件与目录

- 数据库文件：项目根目录 `data/shop.db`，**首次启动自动创建**（若 `data/` 目录不存在也会自动创建）。
- 商品图片目录：`uploads/`，与数据库文件同级。
- 可用 Navicat、DBeaver、DB Browser for SQLite 等任意 SQLite 客户端直接打开 `data/shop.db` 查看。

## 3. 表结构

共三张表，对应三个实体类（位于 `src/main/java/com/coursewise/shopping/domain/`）。

### 3.1 `seller` —— 卖家账号（`SellerEntity.java`）

系统中预置且仅预置一个卖家账号。**密码只存哈希，任何存储位置不得出现明文**（BR-18）。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 自增主键 | PK | |
| username | varchar(64) | NOT NULL, 唯一（`uk_seller_username`） | 登录名 |
| password_hash | varchar(255) | NOT NULL | Spring Security scrypt 编码；兼容旧 `data.json` 遗留的 `scrypt:<salt>:<hex>` 格式 |
| password_changed_at | varchar(32) | | 改密时间戳（BR-19） |

### 3.2 `product` —— 商品（`ProductEntity.java`）

任意时刻至多一件未售出商品。含索引 `idx_product_status (status)`。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 自增主键 | PK | |
| name | varchar(128) | NOT NULL | 商品名，发布后不可改（BR-14） |
| description | varchar(2000) | NOT NULL | 描述 |
| image | varchar(255) | NOT NULL | 形如 `/uploads/p<时间戳>-<随机>.jpg` |
| price_cents | integer | NOT NULL | 价格以"分"存储，避免浮点误差（BR-17） |
| status | varchar(16) | NOT NULL | `active` / `frozen` / `resumed` / `sold` |
| trading_intent_id | integer | 可空，**不建外键** | 当前"交易中"的意向 ID |
| created_at | varchar(32) | NOT NULL | 发布时间 |
| frozen_at | varchar(32) | | 进入冻结的时间（BR-19） |
| result | varchar(32) | | 交易结果，成功时为 `success` |
| result_at | varchar(32) | | 标记结果的时间（BR-19） |

`trading_intent_id` 刻意不建硬外键：交易失败处置会先解绑、后结案，硬外键会挡住合法的中间态，一致性由 Service 层保证。

### 3.3 `intent` —— 购买意向（`IntentEntity.java`）

每次提交都是一条独立记录，不按联系方式合并（BR-10）。含索引 `idx_intent_product (product_id)` 与 `idx_intent_queue (product_id, stage, submitted_at, id)`。

| 列 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | 自增主键 | PK | |
| product_id | integer | NOT NULL，**不建外键** | 关联商品 |
| name | varchar(64) | NOT NULL | 姓名（可凭口令码修改，BR-12） |
| phone | varchar(32) | NOT NULL | 联系电话（可凭口令码修改，BR-12） |
| passcode | varchar(16) | NOT NULL, **UNIQUE** | 口令码，买家认领意向的唯一凭证（BR-13），数据库层兜底防并发重复发放 |
| submitted_at | varchar(32) | NOT NULL | 提交时间，决定排队位次，不可变 |
| stage | varchar(16) | NOT NULL | `queued` / `trading` / `closed` |
| outcome | varchar(16) | 可空 | 终结后的结局：`success` / `voided` / `requeued` / `cancelled` / `unsold` |

说明：
- **排队位次不落库**，由 `(submitted_at, id)` 排序实时计算。
- `product_id` 不建外键的原因：SQLite JDBC 驱动默认 `foreign_keys=OFF`，外键实际不参与执行；商品也永不删除，一致性由服务层保证。
- 枚举列使用显式 `AttributeConverter` 存小写字面量而非 `@Enumerated(EnumType.STRING)`，避免 Hibernate 6 生成 `check (...)` 约束后 SQLite 不支持 `ALTER TABLE ADD CONSTRAINT`，导致后续 `ddl-auto=update` 报错。
- `passcode` 用列级 `unique = true`（内联进 CREATE TABLE）而非表级 `@Table(uniqueConstraints=...)`，因为后者在 Hibernate 6 + SQLite 下建的唯一索引不被识别，建表后会被删掉。

## 4. 首次启动初始化与旧数据迁移

建表与迁移全部由 `ShoppingApplication` 启动时的 `DataMigrationRunner`（`ApplicationRunner`）自动完成，无需手动执行任何脚本。

### 4.1 建表

`ddl-auto=update` 根据 `SellerEntity` / `ProductEntity` / `IntentEntity` 自动建表、补充缺失字段。

### 4.2 默认卖家账号

无卖家账号时自动创建默认账号 `admin`，初始密码取环境变量 `DEFAULT_SELLER_PASSWORD`（缺省 `admin1234`），只存 scrypt 哈希。

### 4.3 旧 `data.json` 一次性迁移

触发条件（任一不满足则跳过，**绝不覆盖已有数据**）：

1. 三张表均为空（全新库）；
2. 配置的旧数据文件存在（`shopping.legacy-data-file`，缺省 `./data.json`，即 `java_rebuild` 分支时代的文件存储版本）。

迁移内容（整体在一个事务内）：

- 卖家账号：密码哈希**原样搬运**，旧 `scrypt:<salt>:<hex>` 格式仍可登录；
- 全部商品（含历史已售商品）；
- 全部意向（含完整意向名单与历史结局）；
- id 与计数器一并保留，确保迁移后 id 不重号、历史引用关系不变。

迁移完成后日志输出：`旧数据迁移完成：N 个商品、M 条意向、卖家账号 1 个`。

## 5. 可配置环境变量（均可选）

| 变量 | 缺省值 | 说明 |
|---|---|---|
| `SHOP_HOST` | `127.0.0.1` | 监听地址 |
| `SHOP_PORT` | `3000` | 监听端口 |
| `SHOP_DB_FILE` | `./data/shop.db` | SQLite 数据库文件路径 |
| `SHOP_UPLOAD_DIR` | `./uploads` | 商品图片目录 |
| `SHOP_DATA_FILE` | `./data.json` | 旧数据文件路径（迁移用） |
| `DEFAULT_SELLER_PASSWORD` | `admin1234` | 默认卖家初始密码 |

> 注意：监听地址/端口刻意不用裸 `HOST`/`PORT` 变量名，统一加 `SHOP_` 前缀，避免被宿主环境注入的同义变量（如 `SERVER__PORT`）意外覆盖。

## 6. 构建/重建数据库的操作步骤

```powershell
# 全新构建：删除旧库文件后直接启动，建表/默认账号/迁移全自动
Remove-Item -Recurse -Force .\data      # 如需重置
.\mvnw.cmd spring-boot:run
```

1. 启动时 Hibernate 按 `ddl-auto=update` 自动创建 `data/shop.db` 及三张表；
2. 若根目录存在 `data.json` 且库为空，自动完成一次性迁移；
3. 无卖家账号时自动创建 `admin`（密码见 `DEFAULT_SELLER_PASSWORD`）；
4. 用 SQLite 客户端打开 `data/shop.db` 即可查看/校验数据。

如需指定库文件位置：

```powershell
$env:SHOP_DB_FILE = "D:\somewhere\shop.db"; .\mvnw.cmd spring-boot:run
```
