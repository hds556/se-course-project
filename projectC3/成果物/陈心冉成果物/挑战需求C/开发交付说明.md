## 2. 与既有行为的差异

| 既有行为 | 本次改为 |
|---|---|
| 卖家可从「客户下单」推进，且能一路标记到「交易完成」 | 只受理已付款订单（已支付 / 商家确认 / 备货完成），推进止于「开始发货」；交易完成由客户确认收货触发 |
| 推进到「开始发货」不要求物流信息 | 单号必填（≤64 字）、公司选填（默认顺丰），状态与物流字段在一条 UPDATE 内原子写入 |
| 卖家取消只回补库存、不产生退款 | 已付款段按原渠道写一条退款回执并回补库存；未付款段仍无退款；取消不填原因、不二次确认 |
| 地址簿只有下单适配层的读取与最小新增 | 完整增删改与设默认；注册填写的地址直接落入地址簿并设为默认 |
| 在售商品可随时手动下架 / 库存调 0 | 存在「已支付 / 商家确认 / 备货完成」订单时拒绝下架与调 0；「开始发货」及之后不再阻塞 |

## 3. 各需求实现要点

### 14207 推进订单状态

1. 推进表显式写成 `paid → confirmed → packed → shipped`，不再使用枚举序号推算。未付款（客户下单 / 待支付）返回 409 且不落库；「开始发货」与终态均无推进入口。
2. 请求体可选 `to`、`trackingNo`、`shipCompany`。显式传 `to` 时只接受「下一格」，跳过、回退、原地都是 409；非法状态值是 400。
3. 推进到「开始发货」时校验 `trackingNo` 非空且不超过 64 字；`shipCompany` 留空按顺丰落库，非法枚举值按 400 处理。通过条件更新接口原子写入状态与 `shipped_at / ship_company / tracking_no`，并保留 `WHERE status = 旧状态` 防止并发重复推进。
4. 订单视图新增 `advanceable / requiresTrackingNo / payChannel / trackingNo / shipCompany` 等字段；页面只按后端字段渲染按钮与弹窗，不自行推导状态机。后台文字明确写「交易完成由客户确认收货触发，不由卖家标记」。

### 14208 卖家取消订单

1. 「交易完成」「已取消」之外的状态都可取消，包含「开始发货」；接口不要求原因、不弹二次确认。
2. 已付款段（已支付 / 商家确认 / 备货完成 / 开始发货）取消时，从订单快照读取原支付渠道与总额，向 `order_refund`（`order_id` 唯一）写一条 `succeeded` 回执；未付款段无回执。渠道不接受调用方指定，缺少原渠道时拒绝取消，避免错误退款。
3. 状态条件更新、退款回执写入与逐明细 `ProductRepository.restoreStock` 同处一个 `ShopWriteTransaction`；先抢到状态更新的一侧才回补与退款，重复点击返回 409 且不会二次回补 / 二次退款。手动下架商品因 `restoreStock` 只恢复 `depleted`，取消后仍保持下架。

### 14260 收货地址管理

1. 复用现有 `address` 表、`AddressEntity` 与 `AddressRepository`，没有重复建表；完整地址簿挂在 `API-22 /api/addresses`，与下单适配层 `/api/checkout/addresses` 并存。
2. 全部写操作走共享写锁，保证同一个客户至多一条 `is_default=true`。新增首条自动默认；设默认会清除其他标记；删除默认后按 `created_at desc, id desc` 把最近一条设为默认（S-17）；编辑默认地址为非默认时也会自动提升最近一条，避免结算页无默认可用。
3. 地址文本非空、去首尾空格、最多 200 字；地址数量不设上限。客户接口只认 `customer_session`，他人地址统一 404，未登录 401。
4. 注册时若填写「默认交易地点」，同一事务内写入地址簿并设为默认（BR-61）；旧库迁移逻辑保留，仅作为历史数据兜底。
5. 订单只保存 `address_snapshot`，地址编辑 / 删除不回写订单。

### 14213 手动下架商品

1. 在 `CatalogService.withdraw` 中调用新增的 `OrderItemRepository.countBlockingOrders`，统计该商品处于「已支付 / 商家确认 / 备货完成」的订单数，存在即返回 409 并提示「存在已付款订单（N 笔）」。
2. 同一规则用于库存调 0（FR-S-06 / C-27），避免用调库存绕过下架拦截；改为正整数、售罄恢复、手动下架后调库存仍沿用既有逻辑，不新增上架或删除入口。
3. 在途订单不受商品下架影响，仍可推进 / 取消；订单取消回补库存时手动下架商品不会自动回 sale。

## 6. 设计约束与遗留

1. 退款沿用现有 `order_refund` 表，一单一回执；卖家取消与客户取消都遵守同一口径，售后明细多次退款不复用该约定。
2. 地址簿与 `/api/checkout/addresses` 共用表与实体，不重复建表或迁移。
3. 物流单号只是录入与展示，物流轨迹仍由现有 `LogisticsSimulator` 模拟，未接真实快递接口。
4. 本次未实现售后处理（FR-S-14 / FR-C-13~14）。
