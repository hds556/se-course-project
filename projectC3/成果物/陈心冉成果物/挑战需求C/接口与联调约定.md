# 接口与联调约定（陈心冉）

以下只列本次新增或改变契约的接口；支付、物流、下单等既有接口保持原样。

## 1. 卖家订单（14207 / 14208）

| 方法路径 | 请求 | 成功响应要点 |
|---|---|---|
| `POST /api/admin/orders/{id}/advance` | 可选 `{}`、`{"to":"confirmed"}`，或 `{"to":"shipped","trackingNo":"SF123","shipCompany":"sf"}` | `status / statusLabel / nextStatus / advanceable / requiresTrackingNo / cancellable`；发货时另有 `trackingNo` 提示 |
| `POST /api/admin/orders/{id}/cancel` | 无请求体，不要求原因 | `status=cancelled / restored[] / restoredQuantity / refunded / refundCents / refundChannel / refundChannelLabel / message` |

规则与错误码：

- `advance` 仅接受 `paid / confirmed / packed`；`placed / pending_payment / shipped / completed / cancelled` 返回 **409**。
- `trackingNo` 缺失、空白或超 64 字返回 **400**，字段名 `trackingNo`；`shipCompany` 非法返回 **400**，字段名 `shipCompany`。
- 显式 `to` 不等于下一格返回 **409**；未知状态值 **400**。
- `cancel` 对 `completed / cancelled` 返回 **409**；已付款段缺少原支付渠道返回 **409**（字段 `payChannel`）。
- 并发重复推进或取消时条件更新影响 0 行，返回 **409**「订单状态已被其他操作变更」，不会二次回补或二次退款。
- `GET /api/admin/orders`、`GET /api/admin/orders/{id}` 新增返回：`paid / payChannel / payChannelLabel / trackingNo / shipCompany / shipCompanyLabel / shippedAt / requiresTrackingNo`；未发货订单这些物流字段为 `null`，页面据此隐藏物流摘要。

## 2. 地址簿（14260）

| 方法路径 | 请求体 | 说明 |
|---|---|---|
| `GET /api/addresses` | — | `{items:[{id,addressText,isDefault,createdAt}]}`，按创建时间倒序 |
| `POST /api/addresses` | `{addressText, isDefault?}` | 201，首条自动默认；`isDefault=true` 时清除其他默认 |
| `PATCH /api/addresses/{id}` | `{addressText?, isDefault?}` | 未传字段保持原值；`isDefault=false` 时自动提升最近一条 |
| `POST /api/addresses/{id}/default` | — | 设默认，其余置非默认 |
| `DELETE /api/addresses/{id}` | — | `{ok,id,newDefaultId}`；删除默认后 `newDefaultId` 为最近一条 |

- 统一 `customer_session`；未登录 **401**，他人地址 **404**（不泄露存在性）。
- `addressText` 非空、最多 200 字，其他校验错误返回 **400**，字段名 `addressText`。
- 每客户 `isDefault=true` 至多一条；数量不设上限。
- 注册接口 `/api/customer/register` 的 `defaultPlace` 现在会同步写入地址簿并设为默认；旧库仍可由 `CheckoutAddressService` 在首次读取时迁移一次。
- 与 `/api/checkout/addresses` 共用同一张 `address` 表；结算页提交的 `addressId` 必须是本人地址，否则下单服务返回 404。

## 3. 商品下架（14213）

- `POST /api/admin/products/{id}/withdraw` 与 `PATCH /api/admin/products/{id}/stock` 共用阻塞规则：该商品存在「已支付 / 商家确认 / 备货完成」订单时返回 **409**，错误文案含「存在已付款订单（N 笔）」。
- 「开始发货」「交易完成」「已取消」以及未付款订单不阻塞；商品下架后在途订单仍可推进 / 取消。
- 对手动下架商品调库存不会改变 `withdrawn` 状态与 `offlineAt`；系统仍不提供重新上架 / 删除商品接口。

## 4. 数据表

- 不新增表。`orders` 沿用现有支付 / 物流字段；`order_refund` 沿用现有回执表（`order_id` 唯一）；`address` 沿用现有实体与表；`product` 沿用 `status / offline_at / version` 字段。
- `OrderItemRepository.countBlockingOrders` 是新增只读查询，用子查询统计去重的订单数，不改任何表结构。
- 升级仍依赖 `ddl-auto=update`；建议部署前备份 `shop.db` 与 `uploads`。

## 5. 运行

JDK 17+，`./mvnw.cmd package && java -jar target/shopping-system-1.0.0.jar`，默认端口 3000。页面截图使用隔离端口 3100 与临时库，未触碰正式数据。
