## 缺陷及复测

|编号|问题|严重程度|关联用例|当前状态|
|---|---|---|---|---|
|DEF-001|5000位数字价格导致发布接口返回500 HTML错误页|P2，中等|AT-051|已修复，复测通过|

卖家登录后，向POST /api/products提交正常商品字段、合法PNG以及由5000个字符9组成的价格。首次执行和单项复现均得到500；原数据文件未改变，上传目录无遗留图片。异常发生在保存数据时，价格整数转字符串超过Python默认4300位限制。

修复在保存商品及图片前拒绝超长、格式错误和超范围金额，返回400 JSON。价格按整数换算分值，最大支持金额为90071992547409.91元。AT-051保留原验收要求；AT-053验证上限精度及重启一致性，AT-054验证超范围拒绝、无写入和拒绝后正常发布。

完整原因、修改文件和各轮验证过程见《缺陷迭代记录报告》。

## 文件完整性

首次测试与修复后回归均在执行前后计算被测文件SHA-256，比较结果一致，changed_paths为空。复核当前修复副本与回归留存清单，文件内容一致。测试脚本禁用Python字节码写入，测试结果保存在项目目录外。

缺陷修复属于两个版本间的代码变更；文件完整性检查比较的是每轮测试执行前后，不表示rebuild-v2与rebuild_v3内容相同。

## 复测方式

使用Python 3.12，按项目requirements.txt安装依赖。将test_shopping_system.py放在项目目录外，结果目录也须位于项目外。

执行完整回归：

```powershell
python test_shopping_system.py --project "项目目录" --report-dir "测试结果目录" --include-existing
```

执行缺陷关联用例：

```powershell
python test_shopping_system.py --project "项目目录" --report-dir "单项结果目录" --case AT-051
```

省略--include-existing时执行54项独立用例。脚本可生成execution.log、results.json及project_manifest.json供复核；这些是运行产物，不是额外交付文件。退出码0表示测试通过且文件完整性不变，1表示失败、错误或完整性变化，2表示参数错误。
